# 给 OMAC 计划的拆分建议（APA v0.2.0 工作台能力迭代）

本文是建议，不是设计。设计以 `docs/solution-design.md` 与附录 A–D、`docs/changes-v0.2.0.md` 第十节为准。

- `--doc` 指向本目录；生成验收文档时一起读 `docs/` 里上面列出的章节。
- 范围边界与上一轮相同：OMAC 只做替身验收。依赖真实模型端点、真实宿主、真实渠道账号、真实邮箱与提醒事项工具、需要本人到场的验收，全部在设计 §20.4 的 L14–L24，由本人在升级后执行，不进本计划。
- 本文没有运行任何实例；对现有代码的描述来自读代码，标了"按代码"的地方请在节点开工时再核一次。

## 2 依赖、关键路径与并行

```
第 1 批（无依赖）   S0   R0   I2   X1   C1
第 2 批            R1(S0)  I1(S0)  L1(S0)  X2(X1)  C2(C1)
第 3 批            R2  R4  R8  R9 (R1…)   R3(R1,X2)   I3(I1,I2,C1)   B1(I1)   L2 L3 (L1)   X3(X2)   C3(C2,I2)
第 4 批            R5(R2,R4)  R6(R2)  B2(B1,R1,R3)  I4 I5 (I3)  W1(L1,I3,R2)  M1(R8,X2)
第 5 批            R7(R6,R5)  R10(R2,R3,R5)  B3(B2)
第 6 批            Z1
```

- **关键路径有两条等长的，都是 6 个节点**：`S0 → R1 → R2 → R5 → R7 → Z1`（原文的存、读、取回与界面），以及 `X1 → X2 → R3 → B2 → B3 → Z1`（入站改动之后才能做预算，预算之后才能做简报带原文）。排期与评审的取舍上让这两条先走。
- **S0 要最先合入，并把各组的表与列一次收齐。** 已有部署跟随主干升级：结构版本 8 第一次被真实账本应用后冻结，之后再缺列只能另起 9（设计 §16.5）。S0 合入前请对照变更清单 WB-01–WB-08 逐条核一遍；S0 之后的节点如果仍要改结构，在节点说明里写明并各带一个新迁移。
- **第 1 批的五个节点互不相干**，可以同时开工：S0 只动迁移声明与夹具，R0 是来源程序一侧的新包，I2 在策略与授权，X1 在入站流水线与能力包加载器，C1 在 CLI。
- 来源原文（R）、导入（I）、链接型材料（L）三组在 S0 之后互相独立；简报（B）只在 B2 与来源原文汇合；聊天处置（C）与其余各组只在 I2 汇合。

## 3 e2e 节点：替身与合成夹具

六个 e2e 节点都只用替身与合成夹具，不连任何真实账号，不调起浏览器；Web 的验收在各 Web 节点里用组件测试完成。新的 e2e 包要登记进仓库的 e2e 包清单（构建任务会检查清单是否齐全），是否进冒烟清单由节点自己判断，默认不进。

| 节点 | 用到的替身与夹具 | 必须断言的 |
|---|---|---|
| R10 | 一个输出标准事件的桩来源脚本（可按参数产出 200 KiB 正文、带信头与附件清单的事件、超过单条上限的事件，并支持 `fetch` 模式回一段固定字节）；对话端点替身与分类端点替身；结构版本 7 的夹具 | 200 KiB 正文入账后逐字节读回；超限事件被拒收且同批其余事件照常落盘、游标推进；token 读到的内容不超过外发范围，Web 登录读到全文，运行凭据 403；裁剪量出现在判断记录与处置载荷里，账本里的原文没变；升级前的事件完整程度为 `legacy` 且照常可读；附件取回后哈希一致；清除之后事件行还在、原文不在 |
| I5 | 合成的计划文件；一张导入授权单（经 Web 登录的 API 签发） | 一条带三次阶段转移和五条进展的已完成事项，时间线与输入一致；导入前后投递表、规则触发记录、跟进 Timer、摘要起草、注入增量、对外事件流（`import.completed` 除外）都没有新增；未完成的事项没有进久未推进；重放新增 0 条；没有授权单、只带原话、来源名不符、超过条数上限各为退出码 23；运行凭据为 4；预检前后账本不变 |

| B3 | 固定的账本夹具（含两个日历来源的事件，其中一条已取消、一条改期；若干建议、待决策、到期与等待的事项；当天完成的事项与进展；一批导入的历史事件）；harness 替身读资料文件并写回 | 各段条目与夹具一致；日程不含已取消的且取最新一版；导入的事件不进当天活动；没有日历来源时日程为空；两个实例各有自己的窗口，同一条知会只进先跑的那一份；原文文件不超过该来源的外发范围与字符预算，范围未选择的来源没有原文文件 |

## 4 规划标记与对照测试

设计先于实现合入，附录 B、C 里本迭代的条目都带 `【规划中（v0.2.0）】`。对照测试对标记的处理有几处容易踩：

- **新命令、新路由、新事件类型、新内置包内容**各占一行，实现的那个节点在同一个变更里去掉标记。
- **给已有命令加标志、给已有路由加参数或请求体**不能把标记加在原行上（原行已实现，带标记会失败），所以设计里另起了一行，第一格（B.1、C.14）或路由格（B.2）不含反引号，对照测试会跳过这种行。**跳过也意味着实现之后没有测试催着去标记**：实现的节点要把这一行的内容并回原行并删掉拆出的行。Z1 用严格模式（`APA_CONFORMANCE_STRICT=1`）兜底，要求标记清零。
- 附录 B.4 里说明载荷的行要以汉字开头，以反引号开头的行会被当成事件类型清单。
- 设计 §17.3 的退出码表没有规划标记机制：本迭代没有新增退出码，只新增了退出码 23 的几个原因，请不要往那张表里加行。
- 设计 §20.4 的本机验证清单行数在一个发布测试里写死，本次已随设计改为 24；清单再增减时要同步那个测试与 `docs/user/upgrade.md`。
- 设计 §21.3 每行第三格必须含"已关闭""已证实"、`L<数字>` 或"接入时"之一；实测项有了结论写回时保留这个形状。
- 泄漏扫描覆盖 `docs/` 与 `.omac/`：示例里不要出现本机路径、真实邮箱与内网地址。文档里不写具体的笔记应用名，这一条没有测试兜底，靠评审。

## 5 其他提醒

- **红线**：内核仍不认识任何笔记应用、邮件工具或宿主的名字。笔记库的打开方式是本人填的 URL 模板；HTML 转文本在来源程序一侧，不进内核；宿主自带聊天界面的识别只写在该宿主的插件目录里。
- **原文不截断是不变量**（设计 §6.14 第 18 条）：评审每个来源程序与内核改动时，找"截到 N 个字符"一类的代码；出现在入账路径上的都不对，出现在调用模型或给 Agent 输出的路径上的要有留痕。
- **导入不触发自动化也是不变量**（第 17 条）：I1 之后新增的任何事件读取方，默认用"现场"读法；I5 的断言逐个订阅方列出，新增订阅方时同步加一条。
- **需要在真实环境才有结论的**（不阻塞节点）：邮件工具能给出多少原文（`MEAS-RAW-MAIL`、`MEAS-RAW-ATTACH`）、宿主自带聊天界面上报的取值（`SPIKE-SESSION-KIND-OWNCHAT`）、提醒事项工具的筛选参数（`MEAS-REM-UNDATED`）、生成端点预算的默认值（`SPIKE-GEN-BUDGET`）。节点按录制样本与替身实现，取不到的部分走设计里写明的兜底。
- **图**：领域模型图与入站流水线图要加上来源原文、导入批次、链接型材料与紧急提醒，放在 Z1；图的 HTML 与 PNG 成对更新。
