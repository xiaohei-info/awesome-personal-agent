# APA v0.2.0 设计修订：相对现行设计的变更清单

对照基线：v0.1 时仓库主干上的设计（`docs/solution-design.md`、附录 A–C、`AGENTS.md`）。修订后的完整文件是 `docs/` 下的主文档与附录 A–D，以及仓库根目录的 `AGENTS.md`。

- 每条末尾方括号里是全局评审结论（下称"评审结论"）的能力编号（A2、B1 …）或拍板题号（Q1–Q14）。
- 凡是改到已有账本数据、事件载荷、配置字段、API、CLI 的条目，单独有一行"**迁移**"。没有这一行的条目是纯加法，或只改文档。
- 章节号指修订后的文档。

## 统计

| 分组 | 条数 | 其中带迁移说明 |
|---|---|---|
| 一、契约与写入路径变更 | 20 | 16 |
| 二、新增能力 | 31 | 6 |
| 三、默认值变更 | 10 | 5 |
| 四、删除或收窄 | 10 | 3 |
| 合计 | 71 | 30 |

另有：文档结构与订正 9 条（第五节，不计入上表）；推翻评审结论细节 7 处、评审结论没有写而由本修订补定的 6 处（第六节）；已知未覆盖 1 项（第七节）；设计确认时的四项决定（第九节）。

评审结论里分档为"首版必须"的 33 项能力（A2–A7、B1–B6、C2–C4、D1–D5、E2–E4、F2–F4、G1–G6、H1）全部有对应条目，对照表在第八节。

## 一、契约与写入路径变更

| # | 变更 | 现行 | 修订后 | 落点 |
|---|---|---|---|---|
| K-01 | 判断型模板的字段 [B1、B2] | `confidence_threshold`、`escalate_to`，选项里可带"需要解释" | 移除这三样。判断型模板改用 `answer_by`（`classifier`、`chat` 的有序列表；`classifier` 只用于是非题）、`band {low, high}`、`on_undecided`（必填）、`single_shot`、`criteria`；生成型模板新增 `relay_to`；新增占位 `instruction_path` | 附录 C.7、§8.3 |
| K-02 | 往上交的语义 [B1] | 一种"升级"：把握低时换一个模板，判断结果取第一级；把握低的"忽略"被丢 | 拆成两种。同题升级：同一题换后端重答（分类端点 → 对话端点）；接力：题目变了，换生成型或任务型。任何一级未定都不静默丢弃，各级未定时取模板声明的保守默认并标"把握低" | §8.3、§8.9 |
| K-03 | 模型端点配置 [B2] | 策略里一个 `model_endpoint` | `judge_endpoint {url, api_key, protocol, model?, locality, timeout_ms, max_batch, max_material_chars}` 与 `generate_endpoint {url, api_key, model, locality}`；`screening_timeout_ms` 移到顶层 | §6.13、§8.7、附录 B.2 |
| K-04 | 概率判断协议（版本 1）[B2] | 无 | 内核与分类端点之间的线上契约：批量题目、每题 `p_yes`、`probability_source`、整批与单题两级错误码；`self_reported` 的概率被拒绝。判断端点按协议分适配器：原生分类模型服务的判断接口 `system-one`（Web 新配时默认）与自建服务的 `probability-judgment/1` 共用批量、重试与健康处置；对话端点经对数概率换算（`chat-logprobs`）是另一种取数方式，是否开放由 `SPIKE-LOGPROB` 决定 | §8.8 |
| K-05 | 判断留痕 [B2、B6、G6] | 每次判断记一条 `run.finished`（`category: judge`）Event | 每道题一条判断记录（新的运行队列类数据，逐级结果、定案者、影子与抽检标记），默认保留 180 天；用到判断的命令在自己的 Event 载荷里带 `judgment` id | §6.16、§8.6、附录 B.2 |
| K-06 | 入站流水线 [A2、B3、B4] | 去重 → 归属 → 规则 → 判断型三选一（建议、忽略、挂靠）；只在把握低时起草 | 六步：去重 → 归属 → 规则 → 初筛（是非题）→ 起草 → 合并与进入 `proposed`。凡进建议流的都起草（标题、摘要、类别、项目、日期、推荐处置）；起草失败不挡路 | §9.3、附录 C.7 |
| K-07 | 来源规则的出口与条件 [A2、A6、A7] | `then` 只有成为建议、忽略、交判断；条件只按类型、来源、发送者 | 出口六种：`proposed`、`ignore`、`screen`、`extract`、`digest`、`alert`。新增 `where[]`（`eq, ne, in, gt, gte, lt, lte, changed, crosses_above, crosses_below`，后三种只用于 `metrics.<名>`）、`project_by: repo_remote \| fixed:<项目> \| draft \| none`、`on_update: refresh \| attach`、`merge_key`、按规则覆盖的模板名 | 附录 C.5、§9.3 |
| K-08 | 来源事件的处置与未判定原因 [B1、F4] | 处置：`pending`、`attached`、`proposed`、`ignored`、`unjudged`、`expired`；原因：`model_unavailable`、`undecided` | 处置新增 `digest`、`alerted`；原因新增 `outbound_unset` 与 `restored`（N-25），`undecided` 不再产生。来源事件新增 `metrics`、`merge_key`、`items[]`、`judgment` | §6.10、§9.3 |
| K-09 | Source 执行契约的标准事件 [A6、B5] | 固定字段 | 新增三个可选字段：`metrics`（数值字典）、`items[]`（聚合消息，每条 `{sender, text, at}`，至多 200 条）、`merge_key`。契约版本号不变 | §9.2 |
| K-10 | 邮件来源的关联键 [A3] | 邮件适配器不产出关联键 | 以线程根邮件的 Message-ID 为关联键，回信与原信共用；邮件规则默认 `on_update: attach` | §9.4、§9.7、附录 D.2 |
| K-11 | 归属：回音让等待中的事项回到可推进 [A3] | 关联键只用于挂到已委派事项，以及刷新来源对象建出的事项 | 新增"挂到本人的事项"：命中未委派、未关闭的事项时记为挂靠消息；事项在 `waiting` 且等的是人或外部时，由内核（操作者 system）转回 `open` 并取消未到期的跟进定时，可撤销。本人可为事项登记关联键 | §9.4、附录 B |
| K-12 | Source 登记与项目的新字段 [B3、F4] | 无 | Source：`default_project`、`outbound {local, external}`；Project：`capture_outbound`。外发范围只能在 Web 设置 | §6.5、§6.10、§14.14 |
| K-13 | 事项与投递的新字段 [C3、C4、B5、E3、A6] | 无 | 事项：`planned_for`（日期）、`proposal {recommend, attach_to?, reason, low_confidence, sources[]}`、进展（带可选日期）。投递：`item` 可为空（`alert` 出口），此时带 `origin` | §6.3、§6.9 |
| K-14 | 新命令与新的稳定事件 [C4、B5、E3] | 无 | 命令：`item.progress`、`proposal.attach`、`proposal.batch`、`inbound.backlog_rules`、`inbound.backlog_score`、`inbound.backlog_rejudge`、`inbound.backlog_restore`。对外稳定事件：`item.progress_added`、`proposal.attached` | §7、§10.1、附录 B.4 |
| K-15 | 会话类型 [F2、Q9] | 凭原话的第二档命令只检查原话与会话引用非空 | 接入方随每次调用上报会话类型（`APA_SESSION_KIND` / `X-APA-Session-Kind`：`direct`、`group`、`unknown`）；凭原话的代答只在 `direct` 下被接受，其余（含未上报）退出码 23，错误码 `session_not_direct`。授权单不受影响 | §14.5、附录 A.1、B.3 |
| K-16 | 跟进到期的处理 [D2、Q3] | `follow_up` 时钟规则经 `do[]` 调判断型三选一 | 内核固定的规则梯度：前 `remind_rounds` 轮各提醒一次并给"已催、再等、放弃"三个动作，之后转 `needs_input` 问去留。判断型只可选地回答"这一轮可以晚点提吗"（`defer_with`）。`follow_up` 规则不再写 `do[]`；新增 `stale` 规则类型 | §7.3、附录 C.4 |
| K-17 | 对话候选捕获的接线 [A5] | 走邮件那套三选一判断，一段对话一条建议，抽取模板没有被调用 | 固定走 `extract` 出口：`capture-prescreen` 预筛，再由 `triage-extract` 抽取，一段对话可出零到多条候选 | §9.3、附录 C.14 |
| K-18 | `disturb.threshold_judge` 的含义 [B1] | 开启后由判断型在"立即送、并入摘要、只留 Web"里三选一 | 开启后判断型只回答"这条决策可以晚点送吗"，只能降低打扰 | §7.4、§8.9 |
| K-19 | 健康信号 [D5] | 十一项 | 十三项：末尾追加 `stalled_delegations`、`clock_lag`，级别都是提醒 | §15.2、附录 B.2 |
| K-20 | Web 入口的启动与登录约束 [E2] | 监听地址不设限制；会话无有效期；口令无长度下限 | 监听非本机地址时必须配置 https 的 `public_url`，否则拒绝启动；登录限速与锁定；口令不少于 12 个字符；会话有绝对与空闲有效期并可吊销 | §14.13、§16.2 |

**迁移**（逐条）：

| # | 迁移对象 | 做法 |
|---|---|---|
| K-01 | 能力包（配置） | 内置包随版本改写。数据目录里覆盖内置包的用户包，只要还带已移除字段或判断型模板缺 `on_undecided`，整包拒绝加载，同名内置包生效；健康视图与 `apa doctor` 逐字段列出要改的地方和 C.7 的对应写法。不设包格式版本号，不做自动转换（附录 C.11） |
| K-03 | 策略（配置）、API | 已存的策略版本不改写：读到 `model_endpoint` 时等同 `generate_endpoint`，位置按 `external`。本人下一次在 Web 保存端点设置时写成新字段。`PUT /settings/model-endpoints` 在本版同时接受旧的请求形状 |
| K-05 | Event 载荷、账本 | 新增判断记录表（账本数据结构版本 2 → 3，只增）。已有的 `run.finished`（`category: judge`）原样保留、可回放，不搬进判断记录，不计入校准统计。Event 载荷只新增可选的 `judgment` 字段 |
| K-06 | 能力包、写入路径 | 内置 `inbound-triage` 的模板从一个判断模板换成 `triage-screen`、`triage-draft`、`triage-extract`。v0.1 已生成的建议不重新起草 |
| K-07 | 能力包（配置） | `then: judge` 仍被接受，等同 `screen`；`project_by: none` 仍被接受，来源登记了默认项目时取默认项目。其余是新增字段 |
| K-08 | 账本数据、API | 已有来源事件原样保留。`unjudged_reason` 为 `undecided` 或为空的旧值原样返回，内核按 `model_unavailable` 对待并参与重判。按处置枚举做穷举判断的调用方要接受两个新值 |
| K-09 | 来源程序 | 三个字段都可选，已有来源程序与脚本不必修改 |
| K-10 | 账本数据 | 已落盘的邮件事件没有线程关联键，不回填：升级前建的"等回音"事项，回信仍会成为新建议（起草时作为"补到已有事项"的候选）。本人可为这类事项手工登记关联键 |
| K-12 | 账本数据、配置 | 新增列。已有来源：`default_project` 为空，`outbound.local` 为 `full`，`outbound.external` 为未选择。**已有部署若用的是外部端点，升级后每个来源要先在 Web 选一次外发范围**；选之前规则判不了的新事件记未判定（`outbound_unset`），健康视图与 `apa doctor` 提示，选定后自动重判 |
| K-13 | 账本数据、渠道 ext | 新增列，旧事项的新字段为空。渠道 ext 会领到 `item` 为空的提醒投递，自行实现的渠道 ext 要能处理；随包附带的 ext 已适配。渠道 ext 协议版本不变 |
| K-14 | 事件订阅方 | 订阅的类型只增不改；订阅方遇到不处理的类型应跳过并推进游标 |
| K-15 | API、CLI、宿主插件 | **没有兼容期**：旧插件不上报会话类型，凭原话的代答一律被拒。宿主插件须与内核一同升级。读取类调用、委派回执、授权单不受影响。在 `SPIKE-SESSION-KIND` 有结论前，首批宿主插件对网关会话报 `unknown`、对终端会话报 `direct` |
| K-16 | 能力包（配置） | 内置 `follow-up` 包改写。用户覆盖包里 `follow_up` 规则带 `do[]` 的被拒绝，提示删除；已排的跟进定时不变，到期时按新梯度处理 |
| K-18 | 策略（配置） | 键名与类型不变。已开启的继续开启，但"只留 Web 未读"这一去向不再由模型选择 |
| K-19 | API | 前十一项的 id 与顺序不变；按总数断言的调用方与测试要改 |
| K-20 | 运行配置、登录会话 | 监听非本机地址的部署在升级前补上 `public_url`，升级预检会报告。已有口令继续有效，长度规则只在设置与修改时检查。已有登录会话在升级后全部失效，本人重新登录一次 |

没有迁移说明的四条（K-02、K-04、K-11、K-17）：只影响升级之后新发生的判断与事件，不触碰已有数据。

## 六、与评审结论不一致的地方

### 6.1 推翻的细节

| # | 评审结论里的写法 | 本修订的做法 | 理由 |
|---|---|---|---|
| 1 | 每级判断留痕写进事件载荷（B2、5.8） | 单独的判断记录，不进 Event 日志；Event 只引用 id（K-05） | 判断量远大于状态变更量，写进追加日志会让审计流被噪声淹没，也没法按保留期清理；校准统计要按题汇总，不适合从事件流里反推 |
| 2 | 条件命中的提醒属于"只提醒本人"，随 D1 默认生效（A6、4.4 第 6 条） | `alert` 出口归动作类，初始只观察，且必须带字段条件（V-01） | 它由外部内容触发，外部发送者可以借它把任意内容推到本人面前；跟进与久未推进的触发源在账本内，不存在这个问题 |
| 3 | 核验门控：带内与高于上限进入核验，端点不可用时交本人（5.4） | 门控题改成"这份回执需要本人核实吗"：是与未定都交本人核实；端点都不可用时不运行，回执标"未核验"（R-03） | 评审结论把任务型查证排在后续（D6），本版门控之后没有"核验"这一步可进，只能交本人。端点不可用时把每份回执都交本人，会在端点故障期间制造一批打扰，标"未核验"与 v0.1 的行为一致 |
| 4 | 投递阈值：高于上限时"降低打扰"，手段未限定（5.4） | 只留一种手段：推迟到合并窗口之后单独投递（K-18） | 三选一里的"只留 Web 未读"等于模型替本人压下一条决策，不符合"模型判断只能收紧"的单调方向 |
| 5 | 外发控制排在第 4 组，与日上限、静音并列（第 9 节） | 提前到关键路径上的 W2，与两端点同做 | 裁剪发生在组织每一次模型调用的地方，与两端点是同一段代码；分两次做等于改两遍调用路径，而且端点接通之后不该有"未受控地外发"的窗口 |
| 6 | "判断未定"的事件在判断配置变化后重新进入重判（5.7 第 2 条） | 新的级联不再产生"未定"这种未判定原因（各级未定时留为建议）；旧数据里的一次性视同 `model_unavailable` 参与重判，不记判断时的配置版本（K-08） | 评审结论的做法要给每条未定事件记住当时的端点配置才能判断"变没变"；把握低不再丢之后这类事件不会再产生，为存量数据加一个字段不值得 |
| 7 | 适配对象的名字只留在各自的适配目录与说明里（Q14） | 另设附录 D，集中收纳来源工具、渠道、端点的名字与实测结论 | 主文档去掉名字以后，实测结论需要一个文档内的落脚处，否则 §21.3 的"写回"没有位置 |

### 6.2 评审结论没有写、本修订补定的
