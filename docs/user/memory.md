# APA 与 Agent 记忆怎么分工

APA 是你工作现场的上下文库：项目、事项、进展与讨论、决定、项目规范与材料都在账本里，任何接入的 Agent 用 `apa` 命令逐级查到它要的东西。很多 Agent 另有自己的记忆，有的是宿主自带的记忆文件，有的是外接的记忆服务（如 Hindsight）。两者并存，各管一半，不互相替代。

## 归谁

| 内容 | 放哪里 | 为什么 |
|---|---|---|
| 项目与事项的现状、历史、进展、决定和经过 | APA | 账本是唯一的真理源，读到的就是现状；记忆里的任务状态会过期，还会和账本打架 |
| 本人确认过的项目约定（这个项目怎么做、要守的规矩） | APA 的项目规范 | 规范经你确认后生效、有版本，会渲染进仓库的 AGENTS.md，换一个 Agent 接入也读得到 |
| 愿意整理成文的环境事实（服务、目录、机器） | APA 的材料，或留在记忆 | 放 APA 可见、可改、有版本；放记忆不用整理 |
| 你的个人偏好、沟通习惯、人际背景 | Agent 的记忆 | APA 不保存个人记忆与人格档案，也不从对话里推断画像 |
| Agent 自己的经验教训 | Agent 的记忆 | 与工作现场无关 |

## Agent 什么时候先查 APA

常驻说明（`apa guide --template`，插件自动安装）已经写明：凡是涉及你的工作，过去的还是现在的，Agent 先用 `apa search <词>` 查 APA，再看自己的记忆；查到的事项状态不抄进记忆。查找的步骤是：

1. `apa search <词>`：跨项目按相关度排，中英文都可以，整句也能搜；可按项目、阶段、时间、类型筛选。
2. `apa item show <id>`：摘要、正文前 2000 字、最近 5 条进展；更早的进展用 `apa item thread <id>`，经过用 `apa why <id>`。
3. 不知道找什么时逐级往下：`apa project list` → `apa project show <id>`（各阶段条数、最近事项、本项目规范）→ `apa item list --project <id>`。

每一步的输出都有上限，并在 `next` 里给出往下一级的命令。

## 项目约定怎么进 APA

你在对话里确认了一条项目约定，Agent 把它写进该项目的规范（`apa material commit`）。规范的修订一律留待你在 Web 确认，确认之前不生效。个人偏好不写进规范，留在 Agent 的记忆里。

## 如果你同时在用外接记忆服务

APA 不读、不写、也不调用任何记忆服务。需要你在记忆服务一侧做的调整（都可选，可以一步一步来）：

1. 让 Agent 在问题涉及项目、任务、进展、决定时先查 APA（常驻说明已写明，记忆服务那边的召回说明可以加同样一句）。
2. 把记忆服务"该记什么"的说明里与任务状态、项目进展有关的部分去掉，只留偏好、纠偏、人的层面与助手经验。
3. 记忆里已有的跨会话项目约定，由你过一遍后写进对应项目的规范。

## 零命中统计

"诊断 › 状态"页的"检索"一栏写明自哪天起检索了几次、几次什么都没找到、几次只找到部分词（`apa health` 的 `search` 同样可查）。它用来判断要不要加语义检索，不是故障。
