# 快速开始

目标：一小时内装好，看到第一次价值，并知道哪里坏了怎么查。

## 1. 安装

从发布包取得与你的系统匹配的 `apa`（单个静态二进制，含内核、CLI、Web 与内置能力包），先核对哈希清单，再放进 `PATH`：

```sh
sha256sum -c SHA256SUMS      # 清单里的每个文件都应为 OK
apa version                  # 版本号、构建提交、各数据结构版本与协议版本
```

不需要编译工具链和源码目录。来源程序、ext、插件包、部署样例都在同一发布包里。

## 2. 初始化与启动

```sh
apa init      # 建立数据目录（默认 ~/.apa，可用 APA_HOME 改写）并设置 Web 登录口令
apa serve     # 启动服务；默认只监听本机
```

口令至少 12 个字符。`apa serve` 默认只监听回环地址，此时不需要任何额外配置。常开主机上请把 `apa serve` 注册成系统服务，样例见发布包里的 `deploy/systemd/`。

## 3. 第一次看到价值

1. 浏览器打开 `apa serve` 打印的本机地址，用刚设的口令登录。
2. 在 Web 新建一个项目和一条事项，给它一个截止日期或计划日期。
3. 打开“今天”视图（Web，或命令行 `apa today`）：到期与计划在今天的事项在这里。
4. 把事项设为“等待”，到期时会有跟进提醒；这一步只需要内核，不需要模型端点和 harness。

## 4. 自检

```sh
apa doctor
```

`apa doctor` 只读，逐项给出结论（正常、提醒、错误）和下一步，并说明你现在处于三档运行形态的哪一档、缺什么才到下一档。退出码 0 表示没有错误级结论，1 表示有。

## 5. 往上加一档（可选）

- 模型端点：在 Web 的“设置 › 模型”配置生成端点，判断端点可选。填好地址和密钥后点“获取模型”从列表里选（取不到就手动填写），再点“测试连接”确认能用，最后保存；每个端点要选在本机还是外部（`locality`）。外部端点会让来源内容离开你的主机，先读[安全说明](security.md)的“外发范围”。
  - 判断端点：协议默认“TypeSafe Jev（System One 接口）”，地址已预填 `https://api.typesafe.ai/v1`、模型 `jev-latest`，填上密钥即可“测试连接”；直连受地区限制时（“测试连接”会提示“服务在当前网络位置不可用”），可填兼容的网关地址：把地址改成网关的接口根（APA 会在后面追加 `/systemone`），模型名按网关的写法填。超时预填 30000 毫秒，因为首次调用可能需要约 10 秒。自己部署的分类服务选“自建分类服务（probability-judgment/1）”，地址填完整路径。不需要写任何转换程序。
- 宿主：在用到的 harness 里安装发布包内的 APA 插件，填入 APA 地址和 token。
- 来源：登记来源时选默认项目和外发范围；附带的拉取程序用 `apa source auth <id>` 认证。

每一档各自能做什么，见[三档运行形态](run-tiers.md)。
