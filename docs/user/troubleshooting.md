# 故障排查

第一步永远是 `apa doctor`：它只读、不改配置，覆盖数据目录与版本、运行配置、运行形态、模型端点、来源、能力包、宿主插件、重复提醒、渠道与导出。`apa doctor --json` 给出结构化结果。Web 健康页能看到内核一侧的同一份检查。

## 症状与处理

| 症状 | 原因 | 处理 |
|---|---|---|
| `apa serve` 拒绝启动，提示 `public_url` | 监听地址不是本机，但没有配置 https 的 `public_url` | 在 `config.yaml` 写上 https 的 `public_url`，或改回只监听本机 |
| `apa serve` 拒绝启动，提示数据结构版本 | 二进制比账本旧；旧版本拒绝打开版本更高的账本 | 换用匹配的新版本二进制；需要退回旧版本见[升级与回退](upgrade.md) |
| 登录返回 429 | 同一来源地址连续失败 5 次后锁定 15 分钟 | 等待 15 分钟；忘记口令时在主机上运行 `apa init --reset-password`，账本不动 |
| 升级后要重新登录 | 升级后已有登录会话全部失效 | 用原口令重新登录一次 |
| 事件停在“未判定”，原因 `outbound_unset` | 来源还没有为外部端点选外发范围 | 在 Web 为该来源选一次外发范围，选定后自动重判 |
| 事件停在“未判定”，原因 `model_unavailable` | 没有可用的模型端点，或端点暂时不可用 | 查 `apa doctor` 的“模型端点”；端点恢复后自动重判（受 `unjudged_rejudge_days` 控制） |
| 事件停在“未判定”，原因 `models_paused` | 你在“设置 › 模型”暂停了模型 | 拨回“运行中”；之后的新事件立即被判断，这些事件按 `unjudged_rejudge_days` 自动重判，或按积压放开处理 |
| 影子打分或放开重判返回退出码 6，`models_paused` | 模型已暂停，这两步需要调用模型 | 先在“设置 › 模型”恢复，再执行；只跑规则不受影响 |
| 聊天里凭原话代答被拒，退出码 23，`session_not_direct` | 会话不是私聊，或宿主插件没有上报会话类型（旧插件） | 在私聊里发起，或把宿主插件与内核一同升级 |
| 提醒比以前少 | 日上限 `disturb.daily_cap`（默认 20）生效，超出的提醒只留 Web 未读；或设置了静音 | 在 Web 查看未读；不想要上限时把 `disturb.daily_cap` 设为 `0` |
| 用户能力包没有生效 | 包里用了已移除字段（如 `confidence_threshold`、`escalate_to`）或判断型模板缺 `on_undecided`，整包被拒绝，同名内置包生效 | 按健康视图或 `apa doctor` 列出的字段改写 |
| 来源认证失败（退出码 2） | 来源凭据过期 | `apa source auth <id>` 重新认证；外部工具的登录用工具自己的命令 |
| 任务型运行拉不起来 | 宿主未安装、未登录或不可执行 | 事项会转 `needs_input`；查 `apa doctor` 的“宿主插件” |

## 看一件事为什么是这样

`apa why <事项或运行 id>` 按 Event 回放来龙去脉：来源事件、命中规则、每一级判断的结果与定案者、接受人、最终决定。入站判断是否“把握低”也在这里看。

## 反馈问题时附上什么

`apa version` 的输出和 `apa doctor --json` 的结果。它们不含账本里的用户内容。不要附上 `config.yaml` 之外的数据目录文件：`sources/` 与 `webhook-keys/` 含凭据。
