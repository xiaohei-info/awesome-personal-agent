# 安全说明

APA 是单用户系统，Web 是最高权限入口：策略、凭据、白名单和高风险决策只能在 Web 处理。

## 远程访问

- 默认只监听本机，零暴露面。
- 要从手机或别的设备访问，必须经 HTTPS（反向代理、隧道或私有网络），并在 `config.yaml` 写上 https 的 `public_url`；监听非本机地址而没有它，`apa serve` 拒绝启动。推荐经私有网络或隧道，不直接暴露到公网。
- 动作链接与投递里的 Web 链接用 `public_url` 拼地址。链接只指向确认页，不含凭据；未登录时先登录，再回到确认页。
- 反向代理必须保留 `Host`，并为 HTTPS 请求带上 `X-Forwarded-Proto: https`。容器用 `--network host` 运行，不要发布端口。样例在发布包的 `deploy/` 下（域名都是占位，换成自己的）。
- webhook 接收路径 `/ingest/` 可单独暴露，其余路径不必公开；`deploy/` 里有只转发 `/ingest/` 的样例。

## 登录与会话

| 措施 | 规则 |
|---|---|
| 登录限速 | 同一来源地址连续失败 5 次后锁定 15 分钟，期间返回 429；15 分钟内全部地址失败超过 20 次时，所有登录尝试延迟应答并记一条 `health.alert` |
| 口令 | 设置与修改时拒绝少于 12 个字符；只存慢哈希；Web 设置里可改口令（需当前口令），改后其他会话全部失效；忘记时在主机上 `apa init --reset-password` |
| 会话 | 绝对有效期默认 30 天、空闲有效期默认 7 天；“设置 › 登录与会话”列出在线会话，可逐个或全部让它退出 |
| 审计 | 登录成功、失败锁定、改口令、吊销会话各记一条 Event，不含口令 |

第二因素认证不在本版。

## 外发范围

来源内容和对话内容会被送到模型端点。端点可能在你的主机上，也可能是外部服务，所以你要知情并可控：

- **端点位置**：判断端点与生成端点各自声明 `locality`（`local` 或 `external`），由你在 Web 的“设置 › 模型”声明，新配端点时必须选；未声明（如 v0.1 留下的配置）按 `external`。模型密钥只写不读，页面只显示末 4 位；已存的密钥只发往原来的主机。
- **来源的外发范围**：只管 APA 自己调模型端点，在“设置 › 模型”的“模型端点能收哪些来源”里按来源选。每个来源有 `outbound.local` 与 `outbound.external`，各取 `full`、`excerpt`、`meta`、`none`。`local` 缺省 `full`；`external` 没有缺省值，不选就不送。
- **对话捕获**：项目的 `capture_outbound` 是对话增量送外部端点的范围，同样没有缺省值，也在“设置 › 模型”里选。
- **未选择时**：规则判不了的事件记未判定（原因 `outbound_unset`），来源页与健康视图提示你去选；选定后自动重判。
- **都不可送时**：来源对所有可用端点的范围都是 `none`，事件改走摘要出口，汇入简报“知会”一节，不进建议流。
- **范围的终点**：外发范围管的是内容进入账本之前的判断与起草。内容经你接受成为事项后，卡片文案、摘要、简报照常用生成端点，任务型运行读到的账本快照进入 Agent 自己的模型，不再按来源范围裁剪。不希望如此的来源请选 `meta` 或 `none`。
- 外发范围只能在 Web 设置，CLI 与委派凭据不能改。`apa doctor` 会报告“有来源向外部端点发送全文”。

## 钥匙读多少

Agent 与外部程序经 API 读到多少来源内容，只看它用的钥匙，与上面的外发范围无关：

- **APA 内部的钥匙**（主 Agent、辅 Agent、本机命令行）：签发时选“APA 内部”，读来源原文、事项与材料都是全文。内部 Agent 用的模型在外部时也一样，签成内部就是你接受了这一点。
- **外部程序的钥匙**：签发时选“外部程序”，再逐个来源选“不给、只有标题、摘要和开头、全部内容”。不选就是不给。同一档也决定它读到的事项正文与材料：一条事项出自几个来源时取最严的那个；没给的来源，相关的事项和材料它看不到。
- 内部还是外部只看钥匙记录，请求从哪里来都不影响；内部钥匙外泄后在任何地方都能读全文，发现外泄就在 Web 吊销。改钥匙的档位要再输一次口令。
- 外发预览、入站记录的原始请求体、被拒行只给你本人和内部钥匙。

内容级脱敏不在本版：本版解决的是知情与范围。

## 三档与 Agent 的档位

- **三档**：整理（Agent 直接做，可在“改动”里撤回）、拍板（回答问题、接受建议、确认修订）、定规矩。定规矩分两半：改日常（来源启停、安排、规则模式、信任的发件人、提醒设置等）和造新权力（发钥匙、填连接与模型凭据、登记来源与可执行命令、改工具权限与启动方式、外发范围、渠道回答人、物理删除、口令与会话）。
- **每个 Agent 一个档位**，在“设置 › Agent”的卡片右栏三选一：只整理（默认）、也替我拍板（可限定项目）、连日常规矩也替我改。卡片左栏是它的钥匙，决定它能碰哪些对象；两者互不重叠。
- **造新权力的事永远只有你能做**，在 Web 上做，而且 10 分钟内要输过一次口令（登录算一次）；任何档位都放不开，Agent 调用一律被拒（退出码 20）并给出设置页链接。
- 放开了拍板的 Agent 替你回答的每一个问题都会推一条提醒，写明它答了什么；在“改动”里可以逐条撤回。回答已经拉起的后台运行撤不回，行上会标出。
- 放开了改日常的 Agent 改的每一项都进“规矩改动”清单，带前值和后值，可以按次撤回，也可以按 Agent 一次撤回。
- 聊天里你对 Agent 说的话不算你的确认：没放开拍板时，Agent 会把卡片链接给你，由你点卡片回答。你也可以在已配对的渠道里直接回复那张卡；不想要这一路，把该渠道的回答人名单清空。
- 外部发送者（邮件、Issue、群消息的作者）的内容只作资料，不作指令。

## 发件人可信

- 每个来源自己声明发件人可不可信，你不能改：GitHub 的作者由平台填写，可信；邮件的发件人是对方自己写的，需确认。
- 可信来源在来源详情里设“信任的发件人”，默认填你自己。名单里的人发来的跟进，Agent 后台运行才能读。
- 需确认来源没有名单：核实不了发件人，后台不会照它的消息办事，自称是你也只给你看。
- 渠道里谁能替你回答，在“设置 › 渠道”里设；Telegram 点“识别我的 ID”，给机器人发一条消息即可。

## 凭据与备份的保管

- `sources/` 含附带拉取程序的第三方凭据，`webhook-keys/` 含 HMAC 接收密钥明文，按敏感数据对待。
- `apa backup create` 的备份默认含这两处，权限 0700；放到别处时请加密保管。`--no-secrets` 不含它们，恢复后需重新认证来源并轮换接收密钥。
- 外部工具的凭据不在数据目录里，换主机需重新认证。
- 要让 Agent 后台运行接触不到你的 delegate token，用专用系统账号运行内核，或不在 APA 主机上给同一账号配置 delegate token。
