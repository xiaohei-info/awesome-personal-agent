## 未发布

- 来源处理结果设为“下次对话时带上”后，只带进你在场的对话，后台运行拿不到；等下次对话期间健康页不再报投递积压，带进过对话的不再堆到 Web 提醒。
- 你或处理 Agent 改过的标题、摘要、正文，不再被同一来源对象的后续更新覆盖。
- “设置 › 来源处理”没选处理 Agent 时用默认 Agent（之前用主 Agent）。
- 点名请你评审的代码托管通知直接进处理队列。覆盖了 `inbound-triage` 包的需自己补上 `pr-review-requested` 规则。
- `apa <命令> --help` 输出用法；新会话与重启后的 Agent 不再收到一批早已结束的旧事项。
- 权限卡取代三档：每个 Agent 一张权限卡，十组动作各自"不允许 / 允许"，后果较大的五组可以限时开放，物理删除只能限时；改权限卡、钥匙、口令与会话、渠道回答人只有你本人能做。Agent 后台运行与主会话同权，工具档位取卡上的值；被拦时说明是哪一组没开、去哪开；`apa why denied` 看最近被拦下的记录。Web 能做的设置都有 CLI 入口（`apa settings`、`apa purge`、`apa connection`）。
- 权限模型改为三档：整理（Agent 直接做，可撤回）、拍板（回答问题、接受建议、确认修订）、定规矩（分改日常与造新权力两半）。每个 Agent 在“设置 › Agent”选一个档位：只整理（默认）、也替我拍板（可限定项目）、连日常规矩也替我改；造新权力的事永远只有你在 Web 做，且要 10 分钟内输过口令。本人原话、会话类型、授权单、高风险类别与模型初筛、问题的超时默认、一次性表单全部取消；渠道里回答人名单内的账号对卡片的回复算你本人。新增“规矩改动”清单（前值、后值、按次或按 Agent 撤回）与 `apa authz preview`。升级时自动切换一次，见“升级”。
- 日历：“今天”下新增“日历”页签，按日、周、月查看排了期的事项（只读，点一件事进事项详情）。事项多了“时段”（如 `14:00 - 15:00`，落在计划日期那天）；有日期没时段的放在“未定时”一栏。计划日期、时段、截止统一在事项详情的“排期”区块改，别处同时改过会提示并让你确认后再存。命令行 `apa item add/update --planned-slot`，`apa item list --from --to` 按日期范围读；`GET /items` 新增 `from`、`to`（附录 B.6）。
- “助手的语气”自带默认：没自己写时，助手用一段内置的语气（靠谱、温和、先说结论、不打官腔，中英各一份），“设置 › 通用”里的编辑框显示它并标“默认”；改了就用你的，点“恢复默认”回到内置的。默认文本随版本更新，没自定义的会自动跟随；新会话生效。“设置 › 通用”新增“助手说哪种语言”（中文 / English / 跟随系统，默认跟随系统），不依赖宿主进程的区域设置；命令行 `apa persona --lang zh|en` 优先于它，没设置时按系统区域设置，都没有用英文。
- 诊断里的“后台运行”改名“运行日志”，改成一行一条的日志：时间、做了什么（如“拉取 Gmail”）、结果、用时，点一行就地展开细节；可按“来源拉取 / agent 任务”和“只看失败”筛选，同一来源连续成功的拉取折成一行，底部“加载更多”。`GET /runs` 的 `state`、`category` 支持逗号分隔，新增翻页参数 `before`（附录 B）。
- CI 分层：PR 与合入 main 只跑构建、单测与冒烟 e2e（约 5 分钟内）；全量 e2e 改为发版门禁，推 `v*` tag 或手动触发 `release` 工作流时运行，通过后才打包发布。
- 界面与文档里的“宿主”“主助手”统一改称 Agent；APA 在你不在时拉起 Agent，叫“Agent 后台运行”。“设置”里的分组与入口随之改名（如“Agent 动态”）；`apa doctor` 的英文说明同步改为 Agent。
- 钥匙决定读多少：签发钥匙时选“APA 内部”或“外部程序”，外部程序再逐个来源选档位（不给、只有标题、摘要和开头、全部内容），同一档也管它读到的事项正文与材料，出自几个来源时取最严。来源页、项目页不再逐个配外发，送模型端点的范围搬到“设置 › 模型”。**升级后要做的**：旧钥匙一律迁成外部钥匙，逐来源档位等于它们原来经 token 读到的（外发范围是全文、摘录的照给，其余只有标题），事项正文与材料从此按档位裁；APA 内部用的钥匙在“设置 › Agent”里改成“APA 内部”即恢复全文。新账本对旧版本是 `ledger_too_new`，回退要用升级前的账本快照。
- Web 建议流忽略建议时，理由改为选填（与 `apa dismiss --reason` 一致）；不填时事件理由记缺省值。

## 0.2.0

v0.2.0 在 v0.1 之上加入判断分层、入站流水线、三档运行形态、备份升级回退与完整发布物。完整的逐条变更与设计依据见 `docs/changes-v0.2.0.md`，契约改动见 `docs/appendix-b-api-cli.md` 的 B.6。

### 工作台能力迭代

v0.2.0 发布前追加的迭代，逐条设计依据见 `docs/changes-v0.2.0.md` 第十节。

- 来源原文完整保留：账本存完整原文，不再截断；Web 的“处理经过”可看原文，“设置 › 存储”看占用并设保留天数，可物理删除来源事件，附件按需取回。
- 带原始时间的导入在发布前取消：不提供 `apa import`、`POST /import` 与“设置 › 导入”，授权单不能再签 `import.apply`。升级前已导入的事项与事件只读保留，“操作记录”仍把一个旧导入批次折叠成一行，它们照旧不触发提醒、规则与跟进。
- 链接型材料与笔记库：在“设置 › 笔记库”登记库与打开方式，材料可登记为链接，回执里的库内链接自动登记为产出。
- 简报资料扩展：日程、新增建议、待决策、到期与等待、当天活动；每个简报实例有自己的取材窗口，可带来源原文。
- 抽取与起草对齐、紧急建议即时提醒：来源规则可声明 `notify_urgent`；没有到期日的提醒事项经 `undated_lists` 进入。
- 聊天里处置建议与记进展：Agent 插件新增三个代答工具；与本人私聊的会话才凭原话生效。

### 界面语言

- Web 界面可在中文与英文之间切换：在“设置 › 通用”里选，登录页右上角也能切。选择只存在这台浏览器上，不跨设备同步。
- **默认跟随浏览器**：浏览器首选语言是中文的显示中文，其他显示英文。升级后如果你的浏览器首选英文，会看到英文界面，在“设置 › 通用”选“中文”一次即可切回。
- 切换只影响 Web 界面文字与日期格式。通知、简报、卡片文案与内置提示词仍为中文；出错时先显示当前语言的一句话，服务端返回的原因说明（错误、健康、自检）保持英文原文。
- CLI 的命令、输出键名和错误码为英文。

### 界面用词

- 阶段、优先级、事件类型、权限档、规则模式等取值在 Web 上显示为名字（如“等你决定”“只看”“试运行”），不再显示 `needs_input`、`read`、`observe` 这类内部 ID。需要核对 ID 时，在“设置 › 通用”打开“显示原始值”。
- 来源页：每个来源一句状态（如“3 分钟前读过”“连续 3 次没读到”）；改外发范围时先预览一条真实消息会送出什么，点“就这样发”才保存；积压按原因显示状态（等模型恢复、模型已暂停、等你选外发范围、已放回等你放开、已过期），积压放开四步做成带进度的引导；入站记录、读取失败的记录、自定义命令来源与“找回升级前被自动忽略的消息”收在“高级”里。
- 来源按名字称呼：界面里凡是出现来源的地方都显示名字，内部 id 只在"显示原始值"里。仓库自带的来源程序登记时自带名字（如"iCloud 邮件""Apple 日历""GitHub"），同一程序的多个账户名字不同；自己写的脚本或程序登记时必须起名（`apa source add --name`、`sources.json` 的 `name`、Web 的名字一栏），不起名会被拒绝。来源页可以行内改名，重名会被拒绝。升级时已有来源自动补名，自己写的脚本按类型起名并在健康视图提示你起名。
- 日常页面不再露出 id：项目、执行者、凭据显示名字；“Web 未读”改名“未读提醒”并标出被日上限或暂停提醒压下的原因；“agent 变更”“任务委派”改名“改动”“委派”，撤销先确认；简报改为选“哪几天、几点”安排（按这台设备的时区），cron 收在高级里。
- 设置按要做的事重新分页：原“策略与人格”拆成“提醒与打扰”“我来拍板”“后台权限”，人格移到“通用”并改称“助手的语气”；凭据、执行者与声明、授权单、登录安全、物理删除改称接入钥匙、执行者、临时授权、登录与会话、永久删除。旧地址都还能打开。
- “提醒与打扰”可以直接设安静时段、低优先级提醒合并和截止后再提醒（以前只能经接口设），日上限下面显示今天已推送了多少条。“模型”页的超时改按秒填写。

- 简报和复盘装好就有：第一次启动（已有部署升级后的第一次启动也一样）会自动安排好“工作日 08:30 简报”和“每周五 17:30 复盘”（按 APA 所在机器的时区），默认开启，只建一次，你停用或改过之后不会被改回来。简报页每个安排一张卡片，点开可改时间、只看哪些项目，以及“跑什么”：默认的写作要求标“默认”并随新版更新，改了就用你的，可“恢复默认”，下次运行生效；还能停用、立即跑一次、打开最近一次的结果。Agent 还不能后台运行时，卡片显示“等 Agent 接入后开始”，到点跳过、不建要你处理的事项，接入后从下一个时间点开始。
- “自动规则 › 规则”不再出现按安排运行的几条（按时写简报、按时写复盘、按时做例行任务）：它们是简报页安排的执行逻辑，不是要你管的规则，要停就在简报页停用对应的安排；接口里也不再列出。
- 事项详情加“交给 Agent 处理”开关（任务事项、未结束时显示），取代手写 `agent-ok` 标签；界面不再露出标签名，事项列表里它显示为“交给 Agent”，规则页对应那条改名“我交给 Agent 的事项自动开工”。开着时旁边一句状态说明还差什么：自动开工没开、试运行只记录、Agent 还不能在后台运行；已经在进行中的事项加上也不会补开工。
- 导航第三组改名“自动化”：“消息来源”（来源、被忽略的，抽几条看看）与“自动规则”（规则、筛选门槛）。原“判断与校准”拆开：抽查在消息来源下，不确定带改在“筛选门槛”上拖两条线设，拖动时显示最近一段时间各段约有多少条，试用（影子）是每个问题上的开关。规则按“提醒我 / 替我动手”分组，模式是“关 / 试运行 / 开”，试运行的规则显示本周本来会做几次。
- 健康改成导航底部的状态灯（运行正常 / 模型已暂停 / n 项要处理）；“诊断”里是状态（只列要处理的，每条一句话加去处）、操作记录（原审计）与后台运行（原运行记录）。原“能力包视图”并进事项列表上方的类型筛选。旧地址都还能打开。
- 补齐以前只能经接口设的几项：来源详情里选“归到哪个项目”，并能看到只进了简报的消息、逐条转成建议；项目开启“从聊天里自动记下待办”后选聊天内容发给外部模型时送多少（不预选）；“设置 › 后台权限”选没指定时用哪个宿主（不设时后台任务会停下来问你）；简报页可以建例行任务（到点让 agent 去做，或只记一条事项），每个定时简报和例行任务都能停用与启用；材料页按标题选关联事项。
- 渠道可在“设置 › 提醒与打扰”设“只能发文字”（决策附一次性表单链接）；简报、复盘与例行任务建好后可以“修改”定时、项目与任务内容，不必删了重建。

### 判断端点

- 判断端点按协议接入，“设置 › 模型”新配时默认 **TypeSafe Jev（System One 接口）**：预填官方地址与 `jev-latest`，填密钥即可测试连接，也能“获取模型”；经网关接入时改地址与模型名。不再需要自己写转换程序。
- 新配 System One 判断端点时超时预填 30 秒（首次调用可能需要约 10 秒）；已保存的配置不变。
- 服务在当前网络位置不可用（HTTP 451，或说明地区受限的 403）时，“测试连接”和健康视图显示“服务在当前网络位置不可用，请改用可访问的网关地址或代理”，不再显示“响应不符合所选协议”。
- 自建分类服务继续用 `probability-judgment/1`。已保存的判断端点配置原样生效，不迁移；接口里省略 `protocol` 仍按 `probability-judgment/1`。

### 生成端点的协议

- “设置 › 模型 › 写作模型”第一项新增“协议”：**OpenAI 兼容**（默认）、**Anthropic 兼容**、**OpenAI Responses**，各用原生的结构化输出方式（`response_format`、强制调用的输出工具、`text.format`），“获取模型”和“测试连接”按所选协议走，测试结果写明协议与结构化输出方式。
- 经网关接 Claude 模型时选“Anthropic 兼容”：网关把对话补全请求转成消息接口时会丢掉结构化约束，起草建议因此逐条失败（“不是单个 JSON 值”）。
- 已保存的生成端点不迁移，没写协议的按“OpenAI 兼容”，行为不变。回退到旧版本前把协议改回“OpenAI 兼容”，旧版本只会按它调用。

### 暂停模型

- “设置 › 模型”顶部新增“运行中 / 已暂停”开关，同时暂停生成端点与判断端点：配置和密钥保留，暂停期间按没配端点运行，恢复后立即按原配置工作。只在配了端点时显示。
- 暂停期间未判定的事件原因记 `models_paused`，与端点故障的 `model_unavailable` 分开；“诊断 › 状态”、导航底部的状态灯与 `apa doctor` 显示“已暂停”，不报故障。
- 暂停时“测试连接”“获取模型”照常可用；积压的影子打分与放开重判被拒（退出码 6，`models_paused`）。
- 已保存的策略默认不暂停，无需迁移。
- 暂停卡、“诊断 › 状态”与来源积压的提示按运行配置 `unjudged_rejudge_days` 说明恢复后怎样处理：大于 0 时“恢复后自动判断（最近 N 天的）”，为 0 时“恢复后在积压里放开”。

### 需要迁移的变更

升级前请逐条确认。升级步骤与回退见[升级说明](upgrade.md)。

| # | 变更 | 你要做什么 |
|---|---|---|
| M-1 | 外发范围需在 Web 选择：已有来源的 `outbound.external` 为未选择，没有默认值 | 使用外部端点的部署，升级后在 Web 为每个来源选一次外发范围。选定之前规则判不了的新事件记未判定（`outbound_unset`），健康视图与 `apa doctor` 提示；选定后自动重判。使用本机端点的来源缺省 `full`，不受影响 |

### 新增

入站六步流水线（去重、归属、规则、初筛、起草、合并）；判断记录与“筛选门槛”“被忽略的，抽几条看看”两页；来源规则的出口 `proposed`、`ignore`、`screen`、`extract`、`digest`、`alert` 与字段条件；规则带提醒类或动作类的类别（`GET /rules` 的 `class`）；“今天”视图、计划日期、进展记录；建议的“补到已有事项”和批量处理；打扰日上限与静音（`GET /deliveries/today` 可读当天已推送几条）；Web 改口令与会话管理；外发控制（`GET /source-events/{id}/outbound-preview` 可预览一条事件在各外发范围下会送出什么）；`apa doctor`；`apa backup create|verify|restore`；升级前自动快照；完整发布物与本用户文档。

### Web 界面调整

- 导航重排：一级入口分“处理、工作、自动化”三组，导航底部是状态灯、“设置”与“诊断”（状态、操作记录、后台运行），同一入口下的页面以页签切换；手机上顶栏只放今天、决策、建议、事项和“更多”。页面地址一个不改，旧书签、动作链接和通知里的链接照常打开。
- 建议流在导航上显示待处理数量。
- 模型端点单独成页（设置 › 模型）：填好地址和密钥后可以“获取模型”从列表里选，再“测试连接”；新配端点时必须选端点在本机还是外部。密钥只显示末 4 位；端点地址换了主机要重新输入密钥。
- 简报抽检条目的链接（`/judgments/…`）现在打开“消息来源 › 被忽略的，抽几条看看”，并标出那一条。
- 每条进来的消息都能看“处理经过”：来源详情新增“最近的消息”（可按提成建议、忽略、挂到事项、积压筛选），点一行就地展开，一行一句写清从哪进来、发件人是否已核实、命中哪条规则或判断模型给了多大把握（落在门槛哪一段）、结果、起草是否成功、后来你和 Agent 做了什么；也可单独打开。建议流的“n 条消息”、事项的跟进消息、抽查条目都能点回这里。
- 事项详情的“时间线”改为“经过”：每行“谁 · 做了什么 · 结果”，不再显示英文原因和内部 id；来自消息的事项开头接上那条消息的经过，派给执行者的子事项并进来；同类的机械记录折成一行；原始记录在“显示原始值”里。v0.2.0 之前的记录里，起草是否成功、抽查点了“确实不用”可能查不到，页面会如实写“不清楚”或“已过保留期”。

### 默认值变更

提醒类规则初始 `auto`；入站把握低时留为建议并标“把握低”；送给外部端点的内容没有默认范围，不选就不送；邮件、日历事件取来源的默认项目；新增配置键取默认值（`judge_endpoint.timeout_ms` 10000、`max_batch` 32、`max_material_chars` 8000、`backlog_release_per_day` 40、`judgment_retention_days` 180、`delegation_stall_after` 24h）。

### 收窄

对话端点不再自报置信度；非私聊会话不接受凭原话的代答；对外定位收窄为面向已经在用 harness 的人，本版支持一个宿主。

### 本版未验证的范围

真实模型端点、真实宿主的端到端验证由你按[升级后本机验证清单 L1–L12](upgrade.md)在本机执行；“中心 APA 加多台 harness 主机”本版未执行。
