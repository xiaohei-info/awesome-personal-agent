# 变更记录

## 未发布

- Web 建议流忽略建议时，理由改为选填（与 `apa dismiss --reason` 一致）；不填时事件理由记缺省值。

## 0.2.0

v0.2.0 在 v0.1 之上加入判断分层、入站流水线、三档运行形态、备份升级回退与完整发布物。完整的逐条变更与设计依据见 `docs/changes-v0.2.0.md`，契约改动见 `docs/appendix-b-api-cli.md` 的 B.6。

### 界面语言

- Web 界面可在中文与英文之间切换：在“设置 › 通用”里选，登录页右上角也能切。选择只存在这台浏览器上，不跨设备同步。
- **默认跟随浏览器**：浏览器首选语言是中文的显示中文，其他显示英文。升级后如果你的浏览器首选英文，会看到英文界面，在“设置 › 通用”选“中文”一次即可切回。
- 切换只影响 Web 界面文字与日期格式。通知、简报、卡片文案与内置提示词仍为中文；服务端返回的原因说明（错误、健康、自检）在两种界面里都显示英文原文。
- CLI 的命令、输出键名和错误码为英文。

### 判断端点

- 判断端点按协议接入，“设置 › 模型”新配时默认 **TypeSafe Jev（System One 接口）**：预填官方地址与 `jev-latest`，填密钥即可测试连接，也能“获取模型”；经网关接入时改地址与模型名。不再需要自己写转换程序。
- 自建分类服务继续用 `probability-judgment/1`。已保存的判断端点配置原样生效，不迁移；接口里省略 `protocol` 仍按 `probability-judgment/1`。

### 需要迁移的变更

升级前请逐条确认。升级步骤与回退见[升级说明](upgrade.md)。

| # | 变更 | 你要做什么 |
|---|---|---|
| M-1 | 外发范围需在 Web 选择：已有来源的 `outbound.external` 为未选择，没有默认值 | 使用外部端点的部署，升级后在 Web 为每个来源选一次外发范围。选定之前规则判不了的新事件记未判定（`outbound_unset`），健康视图与 `apa doctor` 提示；选定后自动重判。使用本机端点的来源缺省 `full`，不受影响 |
| M-2 | 宿主插件须与内核同时升级：凭原话的代答要求会话类型为私聊，没有兼容期 | 插件与内核一起升级。旧插件不上报会话类型，凭原话的代答一律被拒（退出码 23，`session_not_direct`）；读取类调用、委派回执、授权单不受影响 |
| M-3 | 升级后登录会话失效：会话从此带有效期（绝对 30 天、空闲 7 天）与来源信息 | 升级后用原口令重新登录一次；口令继续有效，12 个字符的长度下限只在设置与修改口令时检查 |
| M-4 | 日上限默认生效：新键 `disturb.daily_cap` 默认 20，超出的提醒只留 Web 未读 | 不想要上限时在策略里把 `disturb.daily_cap` 设为 `0`；健康类与 web_only 决策不受限 |
| M-5 | 提醒类规则初始模式改为 `auto`：内置提醒类规则若仍是 v0.1 的初始 `observe` 且你从未切换过，升级时切到 `auto` | 不需要操作；每条切换记 `rule.mode_changed`，并有一条健康类说明。不想要时把对应规则设回 `observe` 或 `off` |
| M-6 | 监听非本机地址的部署必须配置 https 的 `public_url`，否则 `apa serve` 拒绝启动 | 升级前补上；`apa doctor --upgrade-check` 会报告 |
| M-7 | 能力包字段变更：`confidence_threshold`、`escalate_to` 移除，判断型模板须有 `on_undecided`；`follow_up` 规则不再写 `do[]` | 数据目录里覆盖内置包的用户包若仍带旧写法，整包被拒绝、内置包生效；按健康视图列出的字段改写 |
| M-8 | 模型端点配置改为 `judge_endpoint` 与 `generate_endpoint` | 已存的策略不改写；`PUT /settings/model-endpoints` 本版仍接受旧形状。下一次在 Web 保存端点设置时写成新字段，并声明端点位置 |
| M-9 | API 枚举与计数：`unjudged_reason` 新增 `outbound_unset`、`restored`，来源事件处置新增 `digest`、`alerted`；`GET /health` 信号由十一项变十三项 | 按枚举穷举判断的调用方要接受新值；按总数断言的调用方与测试要改 |
| M-10 | 渠道 ext 会领到 `item` 为空的提醒投递（`alert` 出口） | 自行实现的渠道 ext 要能处理空的 `item`；随包附带的 ext 已适配 |
| M-11 | 账本数据结构版本升到 3（只增）；旧版本二进制拒绝打开升级后的账本 | 升级前备份；回退只有恢复快照一条路 |

没有迁移要求的变更是纯加法或只改文档。

### 新增

入站六步流水线（去重、归属、规则、初筛、起草、合并）；判断记录与“判断与校准”页；来源规则的出口 `proposed`、`ignore`、`screen`、`extract`、`digest`、`alert` 与字段条件；“今天”视图、计划日期、进展记录；建议的“补到已有事项”和批量处理；打扰日上限与静音；Web 改口令与会话管理；外发控制；`apa doctor`；`apa backup create|verify|restore`；升级前自动快照；完整发布物与本用户文档。

### Web 界面调整

- 导航重排：一级入口分“处理、工作、运营”三组，“设置”固定在导航底部，同一入口下的页面以页签切换；手机上顶栏只放今天、决策、建议、事项和“更多”。页面地址一个不改，旧书签、动作链接和通知里的链接照常打开。
- 建议流在导航上显示待处理数量。
- 模型端点单独成页（设置 › 模型）：填好地址和密钥后可以“获取模型”从列表里选，再“测试连接”；新配端点时必须选端点在本机还是外部。密钥只显示末 4 位；端点地址换了主机要重新输入密钥。
- 简报抽检条目的链接（`/judgments/…`）现在打开“判断与校准”页。

### 默认值变更

提醒类规则初始 `auto`；入站把握低时留为建议并标“把握低”；送给外部端点的内容没有默认范围，不选就不送；邮件、日历事件取来源的默认项目；新增配置键取默认值（`judge_endpoint.timeout_ms` 10000、`max_batch` 32、`max_material_chars` 8000、`backlog_release_per_day` 40、`judgment_retention_days` 180、`delegation_stall_after` 24h）。

### 收窄

对话端点不再自报置信度；非私聊会话不接受凭原话的代答；对外定位收窄为面向已经在用 harness 的人，本版支持一个宿主。

### 本版未验证的范围

真实模型端点、真实宿主的端到端验证由你按[升级后本机验证清单 L1–L12](upgrade.md)在本机执行；“中心 APA 加多台 harness 主机”本版未执行。
