# Web 界面设计

本文是 Web 中台的界面设计：信息架构、页面职责、每个设置的权威位置、红点与待办的口径、保存方式、主流程、术语与文案，以及各页面的细则。主文档 §4.1 只留概览，界面上的规定以本文为准；内核的规则（账本唯一真理源、web_only、授权、观察模式）以主文档为准，本文不改变它们。

页面按使用者的一条线组织：**有事找我 → 我定 → Agent 去做 → 我看结果**。Web 只调用 HTTP API，不缓存事项状态做判断依据；凡是权限、档位与硬线的判定都在服务端，页面只搬运本人的选择并如实显示服务端的回答。

---

## 1 原则

1. **按使用者的一条线组织**：处理（要我做什么）→ 工作（事情本身与 Agent 的进展）→ 自动化（什么时候不用我）→ 设置（全局的规矩）→ 诊断（出了什么问题）。
2. **状态必带动作**：任何"未……""……失败""等……"的句子，后面紧跟一个能做的按钮；确实没有可做的，就明说并且不计数。
3. **一个设置一个可编辑位置**：别处只放只读摘要加"去改"链接。创建向导可以给初值，创建之后的修改只在权威位置（§4）。
4. **跳转带落点和回程**：链接落到具体对象的具体区块，目标页顶部给"返回刚才的页面"（§3.3）。
5. **地址不变**：页面地址全部保留，旧书签、提醒里的链接、导出文件里的链接照常可用。导航调整只改归类与名称。

## 2 模块与边界

前端分七个模块，全部只经 HTTP API 读写，互不直接调用。

| 模块 | 回答的问题 | 包含页面 | 可写什么（都是本人在 Web 的动作） | 不负责 |
|---|---|---|---|---|
| M0 外壳与公共件 | — | 导航、状态灯、跳转面板、登录 | — | 不含业务判断 |
| M1 处理 | 现在要我做什么 | 今天、等你决定、建议 | 回答问题；接受、补到、忽略建议；完成、改期、写进展；确认提醒 | 不改任何设置 |
| M2 工作 | 事情和资料本身 | 事项、项目、材料、简报（阅读） | 事项与材料的编辑；交给 Agent；现在开始；本事项用哪个 Agent；项目属性与允许的执行者 | 不改全局策略 |
| ~~M3 Agent 工作~~ | ~~我交出去的事怎样了~~ | ~~进行中、改动、规矩改动、执行者~~ | ~~改派、重新委派、撤销改动、撤回规矩改动、移除名录条目~~ | **已变更（2026-11-22）**：这个入口下线。四个页签都是历史记录：进行中的上半是运行记录的子集，改动、规矩改动是审计记录加撤销。改动、规矩改动并进 M6 诊断，带着撤销与撤回；"派给执行者的活"（改派、重新委派）与执行者名录不进导航、地址不变，从状态页、委派事项详情、设置 › Agent 进入（§9.6） |
| M4 自动化 | 什么情况下不用我 | 消息来源（来源、筛选门槛、抽查）、自动规则（规则、定时安排） | 来源设置与积压处理；筛选的线；规则模式；安排的增删改；规则与安排上"用哪个 Agent" | 不处理具体事项 |
| M5 设置 | 全局的规矩和接入 | 日常、Agent 与模型、连接、数据与安全 | 策略、Agent 与程序、钥匙、授权、渠道、模型。Agent 自身属性的唯一可编辑处 | 不展示工作数据，只给"被谁使用"的只读计数 |
| M6 诊断 | 出了什么问题、谁做过什么 | 状态、操作记录、Agent 改动、规矩改动、运行记录 | 只报不修（主文档 §15.2）；例外是 Agent 改动的按次撤销与规矩改动的撤回（**已变更（2026-11-22）**，从原 M3 并入：撤销是这份记录自身的动作，不是修复控件） | 不提供修复控件 |

M0 提供四个公共件，各只有一份实现：

| 公共件 | 作用 | 谁用 |
|---|---|---|
| 注意力汇总 | 一处算出"等你决定、建议、系统要你处理、提醒"，导航角标、状态灯、今天页顶部都取它，数字永远一致 | M0、M1、M6 |
| 前提清单 | 把"这件事还差哪几步才能生效"列成清单，每条没满足的一行状态加一个按钮（就地能做的直接做，否则带落点跳转）；全部满足时不显示 | M1、M2、M5 |
| "用哪个 Agent"选择器 | 显示"现在会用谁、因为什么"；可改为指定某个 Agent，或回到"跟随默认（现在是某某）"；写的是所在对象自己的属性 | M2 事项、M4 规则与安排 |
| 保存反馈 | §6 的三种保存方式与统一的反馈 | 所有带设置的页面 |

模块之间只有两种依赖：**带落点的链接**和**只读摘要**；一个模块不嵌入另一个模块的可编辑控件。例外只有两个：问题卡可以出现在事项详情里（回答是动作，不是设置）；"用哪个 Agent"选择器（写的是当前对象的属性）。M1 与 M6 只向外指；M5 不依赖 M1 到 M3 的数据（只读计数除外）；M3 只读 M2 的事项，不改 Agent。

### 3.3 跳转与回程

跨模块的链接记下来时的地址，目标页顶部显示"返回刚才的页面"；直接打开的页面不显示。链接可带锚点落到具体区块（如 `/settings/agents/<id>#connect`、`/rules#rule-<规则键>`、`/delegation#d-<事项>`、`/items/<id>#agent`）：数据加载后滚到该区块、展开它所在的折叠区并短暂标出。

## 4 设置的权威位置

Agent 相关的东西分五层，各有唯一可编辑位置：

| 层 | 是什么 | 唯一可编辑位置 |
|---|---|---|
| 程序 | 某台机器上的 Agent 程序，以及 APA 在后台启动它的方式 | 设置 › Agent › 添加 Agent 的第一步（接入新的程序）；启动请求的允许或拒绝在该 Agent 页的接入清单 |
| Agent | 基于某个程序的一份配置：名字、模型、工作目录、权限上限、能替我定什么 | 设置 › Agent › 该 Agent 的页面 |
| 分工 | 两个默认：日常 Agent、主 Agent | 设置 › Agent 列表顶部 |
| 指定 | 某条规则、某个安排、某件事指定用哪个 Agent；不指定就按分工 | 那条规则、那个安排、那件事自己的页面 |
| 执行者 | Agent 把活再派出去的对象 | 名录在执行者名录页（`/executors`，**已变更（2026-11-22）**：不进导航，从设置 › Agent 列表的"很少用到"进入）；某项目允许谁，在项目页 |

生效顺序由内核判定：事项指定 > 安排指定 > 规则指定 > 分工默认（主文档 §13.6）。

| 设置项 | 唯一可编辑位置 | 其他页面显示什么 |
|---|---|---|
| 登记一个新程序 | 设置 › Agent › 添加 Agent › 接入新的程序 | — |
| 允许或拒绝在后台启动 | 该 Agent 页 › 接入清单 | 等你决定 › 待确认：一行加"去确认" |

## 5 红点与待办

### 5.1 三种提示，一条总规则

总规则：**没有本人现在就能做的动作，就不提示；被计数的每一件，点进去都落在带主按钮的一行上。**

| 样式 | 含义 | 用在哪 |
|---|---|---|
| 红色实心数字 | 有 n 件事在等你本人，不做就卡住 | 只有"等你决定" |
| 灰色数字 | 有 n 条可以处理，不处理不会卡住任何事 | 建议；抽查（只在自己的页签上，不上浮到"消息来源"入口） |
| 状态灯（红或黄，"n 件要处理"） | 系统有 n 处要你动手才能恢复 | 导航底部；手机"更多"旁的小圆点 |

不提示的情形：本人自己的选择（暂停模型、停用来源、停用渠道、规则设为关）；会自己恢复的（定时器偶尔迟到、等模型恢复的积压）；已经没有可做的事（过期的积压）；同一件事已在别处计数（决策类提醒随问题卡、系统类提醒随状态页）；数据取不到（不显示数字，也不显示"正常"）。

### 5.2 逐个说明

| 提示 | 数字是什么 | 点开首屏 | 下一步按钮 | 何时不出现 |
|---|---|---|---|---|
| 等你决定（红） | 还没回答的问题数，加待确认的条数（Agent 启动请求、等你确认的文档修改） | 问题卡，最紧的在最上；其下是待确认的行 | 卡上的选项；"去确认" | 为 0 |
| 建议（灰） | 未处理的建议条数 | 建议卡 | 接受并交给 Agent、接受、补到已有事项、忽略 | 为 0 |
| 抽查（灰，只在页签上） | 待抽查的被跳过消息条数 | 待抽查列表 | 该看、确实不用 | 为 0 |
| 状态灯 | "要你处理"的行数，按对象计 | 状态页"要你处理"一节 | 每行的主按钮 | 该节为空时写"运行正常"；只有仅供知晓时不亮灯，写"运行正常 · n 条提示"；模型已暂停时是中性的"模型已暂停" |
| 今天页"要你处理" | 上面三个数字的原样汇总 | 三行，各带一句话和按钮 | 去回答、去处理、去看建议 | 三个都为 0 |
| 今天页"Agent 交回的" | 上次打开今天页之后结束的 Agent 运行，按事项各取最近一次；不上导航 | 每件一行：事项、做完或没做完、时间 | 看结果；没做完的"去回答" | 为 0 |
| 今天页"提醒" | 还没确认的提醒，扣除决策类与系统类 | 每条一行：标题、摘要、类别、被压下的原因 | 打开；知道了 | 为 0 |

"上次打开今天页"记在这台浏览器本地，与改动页"自上次访问以来"同一口径，换一台设备会重新算。

**问题卡**：问题原文与截止；是哪件事（标题可点，带项目名）；谁在问、为什么问（一行，默认可见）；选项（有推荐时文字标出，样式不偏向）；"别的想法"。~~"只能你亲自确认"的问题旁一句"这类事只能你在这里定"，"为什么"链到设置 › 我来拍板。~~ **已取消（2026-11-20）**：没有"只能你亲自确认"的问题类别；Agent 替你答过的问题在 Agent 改动里标"Agent 替你答了"。回答之后卡片收成一行回执"已回答：某选项 · 查看事项"，本次停留期间保留。问题卡同样出现在事项详情顶部，所以从今天页、提醒、事项列表任何一处点进去都能直接回答。在这里回答始终是本人在 Web 的动作，不改变任何档位。

**问题只给要你决定的事**（主文档 §6.14 第 20 条）：内核侧不构造只有一个选项又不能写别的想法的问题；运行没跑起来、被拒的 Agent 操作是事件，不进这里、不计红点，分别出现在状态页与事项详情（§5.3、§9.4）；规则动作没完成、运行在拉起前被拒（含续接复核不通过）、来源登录失效同样是事件，只出现在状态页。跑完了没结论的卡选项是"我来处理""放弃"。Web 不逐条过滤问题：进不进"等你决定"由内核的阶段决定。

**内核生成的问题按类别码说人话**：带 `ask.code` 的问题，标题由词表（`web/src/app/vocab.ts` 的 `askCode`）按类别码与参数生成，问题原文与 `params.detail` 收在"详情"里；"谁在问"一行只写谁在问。没有 `code`、由系统问的问题是升级前的旧格式：照原文显示，旁边标"旧格式"。只有一个选项又不能写别的想法的旧卡不显示那个选项，只给一句"这张卡只有一个选项，不需要你决定"和"我知道了"（回答那个选项，事项回到进行中）；这是按问题的形状统一处理，不按卡片内容判断。

**待确认的行**只是摘要加链接，确认仍在权威位置完成（Agent 页的接入清单、材料页）。

### 5.3 状态页逐条

信号本身、判定与清除条件全部沿用服务端与主文档 §15.2；Web 只按对象拆行、归类与措辞，`apa health` 的输出不受影响。每条"要你处理"的行固定三段：**问题一句、影响一句、一个主按钮**，主按钮写要做的事。

| 信号 | 问题 | 影响 | 主按钮与落点 | 归类 |
|---|---|---|---|---|
| 来源读取失败 | "某来源连续 n 次没读到"；登录失效（服务端 `kind` 为 `auth_or_config`，或升级前留下的 `needs_input_item`）时"某来源要重新登录" | 这个来源的新消息进不来 | 去修 → 该来源详情 | 要你处理，每个来源一行 |
| 来源已停用 | "某来源已停用" | — | 去启用 → 该来源 | 仅供知晓 |
| Agent 后台运行超时 | "这件事的 Agent 后台运行超时了" | 这件事没做完 | 看这件事 → 事项详情（找不到目标时去运行记录） | 要你处理，每次运行一行；排队数在仅供知晓 |
| Agent 运行没跑起来（运行故障，带类别码） | 按类别码一句，如退出码 126："执行程序无法启动（没有运行权限）" | "结果没有落账，事项没被修改。"接下一步，如"先在这台电脑上给它运行权限，再重新开始；不修好重跑还会失败" | 看这件事 → 事项详情的 Agent 处理（不给"重新运行"：环境修好前重跑必然失败） | 要你处理，每件事一行；它不是问题，不进"等你决定" |
| 提醒发不出去 | "n 条提醒没送到" | 你可能没收到，暂时放在今天页的提醒里 | 去看渠道 → 提醒渠道 | 要你处理 |
| 自动连锁被叫停 | "Agent 连续自动派活层数太多，被拦下了" | 那件事停在半路，要你再派一次 | 看这件事 → 事项详情 | 要你处理，每件一行 |
| 仓库规范不一致 | "n 个仓库的规范文件和 APA 里的不一样" | Agent 在这些仓库里看到的规范可能是旧的 | 去看项目 | 要你处理 |
| 能力包没加载上 | "n 个能力包没加载上，暂用上一个版本" | 修好包文件后会自动重新加载 | 无网页动作；原因在显示原始值里 | 要你处理 |
| 模型没配置或连不上 | "写作模型还没配置，有消息在等它"；"打分模型连续调用失败" | 新消息暂时筛不了；建议和简报暂时写不出来 | 去配置、去测试连接 → 设置 › 模型 | 要你处理，每个模型一行 |
| 模型已暂停 | "模型已暂停，积下 n 条" | — | 去恢复 | 仅供知晓 |
| 积压：等你选外发范围 | "n 条消息在等你选发给模型多少内容" | 选之前这些消息不会被筛 | 去选 → 来源 | 要你处理 |
| 积压：已放回，等你放开 | "n 条找回的消息等你放进建议" | — | 去放开 → 来源 | 要你处理 |
| 积压：等模型恢复、暂停期间积下、已过期 | 一句话，带会不会自动处理（随重判窗口） | — | 无（暂停期间积下的给"去看来源"） | 仅供知晓 |
| 规则被退回试运行 | "「某规则」的内容变了，已退回试运行" | 它现在只记录，不动手 | 去重新打开 → 那条规则 | 要你处理，每条规则一行 |
| Agent 交回被拒 | 每条一行，原因按服务端的三种口径说人话："它的档位没放开这一步"（`tier_closed`）、"这一步只有你能做"（`hard_line`）、"超出了它的钥匙范围"（`out_of_scope`）；旧记录的原因码照旧说人话；没有原因码时写"原因没有记下，去操作记录看" | 结果没有落账，事项没被修改 | 按原因：档位没放开的"去看档位" → 该 Agent 页；只有你能做的"去处理" → 错误里的页面；超出范围的"看这个 Agent 的钥匙"；其余"看被拒的原因"。次按钮"看被拒的原因" → 操作记录（按对象筛选） | 要你处理，每次被拒一行 |
| 动作没能完成（`other_alerts` 的 `notices`，带类别码） | 按类别码一句，如"需要的模型还没接"、"没能开始：<原因>" | 规则建的那一份："这一份已作废；修好后点「立即跑一次」，旧的也能重开"；其余："事项没被修改；修好后点「现在开工」" | 有专门修法时主按钮写修法（去接模型、去恢复 → 设置 › 模型；去选外发范围 → 来源），次按钮"看这件事"；其余主按钮"看这件事" → 事项详情（没有事项时去操作记录） | 要你处理，每条一行；它不是问题，不进"等你决定" |
| 其他告警（升级前没有类别码的） | "n 条其他告警" | — | 去看 → 操作记录 | 要你处理 |
| 派出去的活久无回音 | "某事项派出去超过 24 小时没回音" | 这件事可能停了 | 去催或改派 → 进行中的那一行 | 要你处理 |
| 定时器迟到 | "n 个定时迟到了；常发生时检查主机是否休眠" | — | 无 | 仅供知晓 |

## 6 保存与反馈

### 6.1 三种保存方式，按风险选

| 类型 | 适用 | 交互 | 反馈 |
|---|---|---|---|
| 即改即存 | 单个开关或单选，可随时改回，不扩大权限：规则模式、用哪个 Agent、在哪里做、分工、界面语言 | 改了就存 | 控件旁短暂写"已保存"；失败时控件回到原值，旁边写原因 |
| 整块保存 | 多个字段共同表达一件事：Agent 基本信息、提醒与打扰的每一节、模型的一个端点、匹配规则 | 每块一个保存按钮；有改动时标题旁标"未保存" | 就地写"已保存"；错误写在出错的那一块里；离开页面时若有未保存的改动，先问一句 |
| 先看后果再确认 | 扩大权限或影响范围、不可撤回：完全放开、放开档位、允许在后台启动、外发范围、作废钥匙、删除 | 先出一句话的后果预览，再确认 | 同上；确认按钮写具体动作 |
| 再输一次口令 | 造新权力的操作（发钥匙、填连接与模型凭据、登记来源、改工具权限与启动方式、改档位、外发范围、渠道回答人、物理删除、作废会话），距上次输口令超过 10 分钟时 | 服务端回 `reauth_required`，页面弹出口令框，输对后自动重试原操作 | 输错就地写原因；连续输错与登录一样会被锁定 |

接口仍按策略的段替换，这是实现细节；界面上的一块按使用者的一件事切。提醒与打扰拆成"各类提醒怎么送、每天最多发几条、暂停提醒、安静时段、更多"五节，每节保存时发整段打扰策略：已保存的原样带回，只换这一节改过的字段，别的节没保存的草稿不带上。Agent 页、提醒与打扰的各节与对我说话的语言、语气在没有改动时保存不可点；其余页面的卡片仍可直接保存，载荷与改版前一致。

### 6.2 通用规则

1. 保存成功只说"已保存"，不带版本号；版本号只在显示原始值里出现。
2. 每个状态句后面跟动作，例如"给它一把钥匙"旁是"生成钥匙"；"还没收到它的启动请求"下是在它所在机器上要运行的那条命令。
3. 只显示一次的钥匙明文出现在触发它的按钮旁，不放到页面顶部。
4. 对象超过两三个、每个对象的设置超过一屏时用列表加单页（Agent 适用；渠道现状保留卡片）。
5. 新建之后直接进入该对象的页面，由清单带着做完剩下的步骤。
6. 技术参数进"高级"，默认折叠：启动命令原文、会话参数、关联键、定时表达式、超时与批量上限。
7. 原始数据（声明原文、ID、英文原因）只在显示原始值打开时出现，或收在"高级"里。

### 6.3 Agent 页面

| 步骤 | 页面与动作 |
|---|---|
| 1 | 设置 › Agent › 添加 Agent：选用哪个程序（没有就选"接入新的程序"，逐项填写它的启动方式），填名字，点创建，直接进入这个 Agent 的页面 |
| 2 | 页面顶部接入清单"还差 n 步就能用"：①给它一把钥匙，点"生成钥匙"，明文就在这一行，点"我已保存"；②允许 APA 在后台启动它，点"查看并允许"，先看到它要运行的命令再允许或拒绝。没收到启动请求时写"还没收到它的启动请求"并给出要在它所在机器上运行的命令。归属不明、最近由这个程序使用的钥匙在清单里一行"归给它" |
| 3 | 清单全部完成后写"已接好，可以用了"。后台权限默认"只看"，要放大在后台权限一块改，选"完全放开"先列出这一档给它的全部工具再确认；档位默认"只整理"，改成更高的档先预览一句"将允许：……"，确认后生效 |
| 4 | 页面上一行说它现在是不是日常或主 Agent，链到列表顶部的分工 |

在哪里做：单选"单独在后台做（不打扰对话）"或"在和你的对话里接着做"，即改即存；程序不支持唤醒时第二项置灰，说明还缺哪一项，"怎么打开"折叠逐项列出。待确认的启动请求改了能不能在对话里接着做时，清单里多一行"这次变化：……"。被谁使用：多少条规则、多少个定时安排、多少件进行中的事单独指定了它，各链到对应页面；没有时写"没有规则、安排或事项单独指定它"。高级：这个 Agent 的钥匙（"给谁"两张单选卡片：Agent 本人、执行者交回结果，各带一句能做什么、不能做什么；作废前先确认）与启动方式原文。

## 7 主流程

### 路径一：收到建议 → 接受 → 交给 Agent → 看结果

| 步 | 页面 | 点什么 | 看到什么 |
|---|---|---|---|
| 1 | 今天 | "n 条新建议 · 去看建议" | 建议页 |
| 2 | 建议 | 某张卡的"接受并交给 Agent" | 前提都满足：先给这条建议加上"交给 Agent"再接受，事项进入进行中时带着标记，规则据此在后台启动 Agent；卡片收成回执"已接受 · 已交给某某，排队中 · 查看事项"。有前提没满足：只接受、不交出，回执写"已接受，还没交给 Agent"，并列出前提清单（如"「我交给 Agent 的事自动开始」在试运行，只记录 · 去打开"），每条带落点与回程 |
| 3 | 今天 | 稍后"Agent 交回的"出现一行"某事项 · 做完了 · 看结果" | 事项详情的 Agent 处理 |
| 4 | 事项详情 | Agent 处理 | 谁做的、状态与时间，链到运行记录；经过里是它交回的结果 |
| 4′ | 等你决定 | 没做完时多一张卡 | 选一个选项；回执后回到事项 |

已在进行中的事项交给 Agent：事项详情的 Agent 处理里点"现在开始"（主文档 §13.6 的 `item.start`，只有本人在 Web 能点）。它不看规则模式，仍受权限上限、项目允许的执行者、链路深度与在途运行约束，不通过时照旧转等你决定。

### 路径二：Agent 问我 → 我回答 → 它继续

导航"等你决定"的红色数字或提醒里的链接 → 问题卡（是哪件事、谁在问、为什么问）→ 想看背景时点事项标题，事项详情顶部是同一张问题卡 → 选一个选项或写别的想法 → 回执，红色数字减一 → 事项回到进行中，Agent 处理区块显示它接着做的情况。

### 路径三：状态灯亮了 → 看懂 → 修好 → 回来

导航底部"2 件要处理" → 状态页"要你处理"两行（问题、影响、按钮）→ 点"去修"，落到该来源详情的出问题处，页面顶部"返回刚才的页面" → 修好 → 返回，那一行已消失，状态灯变成"1 件要处理"。

### 路径四：第一次接入一个 Agent

见 §6.3。本人还没选过分工时，列表顶部分工两行写"还没选，交给 Agent 的事会停下来问你"。

### 路径五：让 Agent 每周定时做一件事

自动规则 › 定时安排 › 新的例行任务：标题、要它做的事、哪几天几点、归到哪个项目；"用哪个 Agent"保持"跟随默认（现在是某某）"，下面只读一行"某某的上限：只看"；选的权限档超出上限时写"超出某某的上限（只看），到点会停下来问你 · 去改上限"，落到该 Agent 的页面 → 安排 → 列表多一行，可"立即跑一次" → 到点后今天页"Agent 交回的"多一行；没做完则在等你决定出现一张卡。

## 8 术语与文案

### 8.1 词表

界面的中英词表（`web/src/app/vocab.ts`）是叫法的唯一出处；新词先进词表，页面不自己造词。下表左列的旧说法在界面上不再出现（显示原始值除外）。

| 概念 | 不再使用 | 统一为 |
|---|---|---|

### 8.2 文案原则

1. **状态加动作**：一句状态后面跟一个按钮；写不出按钮，就写"不用处理"。
2. **站在使用者这边**：主语用"你"和 Agent 的名字。不用本人、宿主、声明、实例、端点、账本、注入、投递、拉起、回执、授权单这些词；它们只出现在显示原始值里和诊断区。
3. **按钮写要做的事**：用"重新登录""去选""查看并允许""去改上限"，不用"去看某页"。
4. **一句话为限**：标题和按钮本身就是说明；需要解释的收进"了解更多"，技术参数进"高级"。页面上的说明文字有预算：不出现成段解释（单条不超过 40 个字），主界面不出现账本、注入、级联等机制词，"后台运行"只作"Agent 后台运行"出现（`web/src/app/text-budget.test.ts`）。
5. **数字带对象**：写"3 件事等你决定"，不写"3 项要处理"。
6. **影响先于原因**：先说对你有什么影响，再说原因。
7. **空状态给起点**：一句这里会出现什么，加一个开始的按钮；空的分组不显示。
8. **保存反馈**：成功只说"已保存"；失败说哪里不对、怎么改。
9. **内核生成的文字**：内核给的是类别码与参数（问题的 `ask.code`、运行的 `fault.code`、被拒的原因码），Web 按词表说人话，技术细节（退出码、英文原因、问题原文）收在"详情"或显示原始值里。没有类别码的旧文字照原文显示，不在前端按文字内容改写或过滤。

## 9 页面细则

### 9.1 今天

数据来自 `GET /today`（计划今天或更早、今天到期、待决、久未推进四组，主文档 §7.3）与注意力汇总。今天的事把计划今天或更早与今天到期合并，同一件只列一次；有时段的行带时段标签、排在前面并按开始时间排。每行一个"完成"，改计划日期与写进展收在"改期、写进展"里；这里的改期只改计划日期，时段不动。久未推进默认折叠，可多选后批量"继续""改期""放弃"，逐条走既有接口、各自成败。Agent 交回的取自 `GET /runs`（Agent 运行、已结束、上次打开今天页之后），链到事项详情的 Agent 处理。提醒取自 `GET /deliveries/unread`，扣除决策类与系统类，最新在前；被日上限或暂停压下的标出原因；在聊天里提过的照样可见，提过不算确认；只有本人点"知道了"才确认。每行在日期前带项目名，点它进项目页。页底一行中性的"今天完成 n 件 · 本周完成 m 件 · 看已完成"（本周一件没有时写"本周还没有完成的事"）：做完的事从上面消失后仍看得到进度，明细只在已完成页，今天页不重复列（**已变更（2026-11-23）**）。

### 9.2 等你决定

问题取自 `GET /items?phase=needs_input` 中还没回答的，截止早的在前，同截止按优先级。待确认取自 `GET /settings/declarations`（Agent 的启动请求）与 `GET /revisions/pending`（等你确认的文档修改），各一行加"去确认"，落到该 Agent 的接入清单或该材料。可以只用键盘处理：数字键 1–9 回答当前卡片的对应选项，J、K 切换卡片；焦点在输入框里时不生效。web_only 初筛还没返回的问题带"风险检查中"标记。被拒绝的代答在卡上标出操作者、原因与授权。

### 9.3 建议

`proposed` 事项，每条带标题、摘要、来源数（链到消息的处理经过）、推荐处置及理由；"把握低"带一句"打分落在不确定的区间，值得你看一眼"。可按来源、项目筛选；"按推荐处理"先列出各处置的条数，确认后批量处理，逐条给出结果。接受并交给 Agent 见 §7 路径一。处理完的建议收成回执并链到事项（补到时链到目标事项）。

### 9.4 事项

列表可按阶段、项目、标签、执行者筛选，按更新时间、截止、计划日期、优先级排序，支持全文搜索；列表上方按类型筛选（全部，以及能力包声明了视图的类型），选中某类型时的列、筛选与卡片字段来自能力包的视图声明。**已变更（2026-11-22）**：筛选是项目、类型、阶段、优先级、有无计划日期、来源、标签七个维度加全文与计划日期；每个下拉的选项带条数，按其余筛选都生效时的条数从多到少排，只剩一种取值的维度不显示；生效的控件描边加深，列表上方一行"正在筛：…"逐项可去掉，另有"清除全部"；快捷类型按钮按下即反色，进入快捷类型时只显示它声明的筛选。每页 50 条，上一页、下一页带"第 x–y 条，共 N 条"，换筛选回到第一页；筛选与页码写在地址里，从详情返回时保留。全文、排序、计划日期仍由服务端做，其余在取回的列表上筛（个人规模）。标签 `agent-ok` 在界面上一律显示为"交给 Agent"，不露出标签名。

详情自上而下：①标题；一句"现在：某阶段 · 项目 · 截止"；随阶段的主操作——等你决定时是问题卡，建议阶段是接受与忽略，进行中是完成（**已变更（2026-11-22）**：除建议外，主操作区列出能去的阶段一键改——进行中：完成、转为等待…；等待中：完成、回到进行中；已完成或不做了：重新打开；等待要填等什么、委派完成要填证据时就地展开再确认，理由自动写明在事项页改的）。事项上最近一次被拒、还没被后续变更取代的 Agent 操作在这里标一行：谁的什么操作被拒、原因（有细分原因 `reason` 时按它，否则按原因码）、"事项未被修改（未生效）"，加"去签发授权"；原因是"初筛待定、授权暂不可用"时写"这个事项的分类结果还在回来，先把卡片里那件事处理掉，或者等一会儿再试"，按钮改为"先处理这件事的卡"（授权本身没问题，卡处理后同一张授权自动恢复可用）；最近一次 Agent 运行没跑起来时也标一行：出了什么事、结果没落账、下一步（不分 kind，简报同样有）。②Agent 处理（任务事项、未结束时）：交给 Agent 的开关、这件事用哪个 Agent、最近一次运行（谁、状态、时间，链到运行记录）、前提清单、进行中且没有在途运行时的"现在开始"。③排期：计划日期、时段（开始与结束两个时间，可选"不定时"）、截止（日期，可选具体时刻），整块保存；这是这三项唯一可编辑的位置。保存带事项版本号，版本对不上时写"这件事刚被别处改过"，载入最新值，本人刚填的留在表单里并标出与最新值不同的项，确认后重新保存。清掉计划日期时时段一起清掉。只到日的截止（本机时间恰好 23:59:59）只显示日期。④渲染后的 Markdown 正文与编辑；挂靠消息。⑤进展与"经过"：一行一句"谁 · 做了什么 · 结果"，谁只写你、Agent、APA 规则、打分模型或写作模型、系统；来自来源消息的事项开头先接上那条消息的处理经过，派出去的子事项并进来；相邻的同类机械记录折成一行；事件名、id 与载荷只在显示原始值里（主文档 §15.1）。⑥更多操作（折叠）：状态标签、~~转阶段~~、关联、材料、关联键；**已变更（2026-11-22）**：转阶段搬到①，这里只留"不做了…"（二次确认、可写为什么）、委派事项的"改派或重新委派"与上述低频项；删除仍在设置 › 永久删除。

预填新建页：`/new` 与 `/items/new` 接受查询参数 `title`、`body`、`link`、`project`、`planned_for`、`planned_slot`、`deadline`，打开后是填好的新建表单（`planned_slot` 只在同时有合法的 `planned_for` 时生效）。新建页每次打开生成一个幂等键，连点两次或网络重试都只建出一件；新建完成后进入新事项，"返回刚才的页面"回到打开新建页之前的页面，页头标明"内容由链接预填"。只预填、不提交，地址不带凭据，未登录时先到登录页再回来。`project` 可以是项目 id 或名字，认不出时留空；`title` 超过 200 个字符、`body` 超过 4000 个字符的部分丢弃并提示。`link` 选了项目且位置合法时，新建成功后登记为链接型材料并以"依据"关联到新事项；否则作为一行链接写在正文末尾。预填内容来自外部，按不可信文本处理。

### 9.5 项目与材料

项目：事项、材料、规范三个视图，repos 属性、允许的执行者（从执行者名录里选，或按机器、按 Agent 匹配）、从聊天记事的开关与它的外发范围（与来源同一组选项，不预选）。材料：自有型是 Markdown 编辑器、版本列表与差异、等你确认的修改（确认、拒绝）；托管型只读展示并标明提交，读不到时只显示登记信息和"暂不可读"。

**已变更（2026-11-23）**：项目详情首屏是这个项目的事，按阶段分组——等你决定、进行中、在等别人（各带条数，计划日期写在行尾）；建议不在这里处理，只写"另有 n 条建议还没处理 · 去看建议"；已完成默认收起，最近完成的在前、写完成那天；不做了的不列。材料在事项之后；名称、简介、标签、状态、从聊天记事、仓库、允许的执行者收进页底折叠的"项目设置"，仍是它们唯一的编辑处。项目不作为事项列表的分组维度：事项列表已有项目筛选，"这个项目怎么样了"由项目页回答。

### 9.6 Agent 工作

**已变更（2026-11-22）**：这个入口下线（本人："进行中、执行者看起来也是在看执行历史，改动、规矩改动像是可以放到诊断或操作记录里"）。原来从这里能到的东西，现在的去处：

| 原来 | 现在 |
|---|---|
| 进行中 › Agent 在后台做的 | 诊断 › 运行记录（"Agent 的运行"）；事项详情 › Agent 处理的最近一次运行 |
| 进行中 › 派给执行者的（改派、重新委派、久无回音） | `/delegation`"派给执行者的活"，不进导航；从状态页"派出去的活久无回音"直达那一行，委派事项详情 › 更多操作"改派或重新委派" |

| 规矩改动（撤回） | 诊断 › 规矩改动（`/rule-changes`，`?agent=<id>` 预选 Agent） |

每个 Agent 页的"它做过什么"直达它的 Agent 改动、规矩改动与运行记录。地址、接口与数据都不变。以下是原条款。

进行中：上面是 Agent 在后台做的事（`GET /runs`，按事项取最近一次，在途的在前），每行事项、哪个 Agent、状态与时间，链到事项详情；下面是派给执行者的活：谁在做、做到哪、证据、长时间没交回的标"久无回音"（取自健康信号），可改派或重新委派（名单外的仍可选，由服务端判定）。改动：自上次访问以来 Agent 做的变更、经聊天或授权代答的决定、观察记录，可撤销或回退（确认里写明外部已发生的不会收回）。执行者：每个执行者一张卡，列手上的事、最近交回的结果与证据、可续接的会话；可移除空闲的名录条目。

### 9.7 消息来源

来源：来源登记、默认项目、外发范围、最近成功、连续失败、积压；"最近的消息"从新到旧列出这个来源进来的全部消息，点一行就地展开它的处理经过，也可单独打开（`/sources/events/<id>`）。操作：启停、设默认项目、看只进了简报的事件并逐条转为建议、设外发范围（先看一条真实消息在所选范围下会送出什么，确认后才保存）、管理接收钥匙、重放、把积压转为建议或忽略、积压放开四步（只跑规则 → 试打分 → 定自动处理的线 → 放进建议；带进度，每步一个按钮；模型暂停时需要模型的两步不可用）、把旧级联忽略的事件放回积压；排障与一次性操作收在"高级"里。信任的发件人：来源程序声明为可信的给一个输入框；声明为需确认的只有一行"核实不了发件人"。

来源原文页（`/sources/events/:id`）："处理经过"之外加"原文"一栏：正文按纯文本显示并保留换行；头部字段成表；附件列出名字、类型与大小，来源程序支持时可"取回"；按会话聚合的事件逐条列出发送者、时刻与文字；有未经转换的原始正文时可切到"原始格式"，只作文本显示，不加载外部资源。页头标明原文大小与完整程度。"送给模型的内容"沿用外发预览（主文档 §14.14）。本页可物理删除这条来源事件。

筛选门槛：每个筛选问题一张卡，误丢率与接受率、分数分布、当前的两条线与试运行状态；在分数分布上拖动两条线并保存，恢复默认，开关试运行（都只在 Web）。抽查：被初筛跳过、待本人抽查的消息，逐条判"该看（转成建议）"或"确实不用"；改每份简报的抽查条数。

### 9.8 自动规则

规则：能力包规则按类别分"提醒我"与"替我动手"，每条显示名字与当前模式（关、试运行、开）；试运行的显示本周"本来会做"的次数与记录；以 Agent 本人身份运行的规则另有"在哪里做"（跟随默认、单独在后台做、在对话里接着做）；带后台运行的规则默认收成一行"由某某处理"，点"改"展开选择器。模式、用哪个 Agent、在哪里做都只在 Web 改、即改即存。由实例驱动的时钟规则不在这里出现，在定时安排里管理。

定时安排（`/briefs/schedule`）：定时简报与复盘每个安排一张卡，收起时一行摘要（如"工作日 08:30 · 开"），Agent 还不能后台运行时写明等它接入；展开后改什么时候、看哪些项目、让 Agent 写什么（没改时显示能力包的默认要求并标"默认"，改了标"已改"，可恢复默认）、用哪个 Agent，启停，立即跑一次（表单有没保存的改动时不可点）。例行任务：到点由 Agent 运行或只建一条事项；到点运行时选权限档，旁边只读该 Agent 的上限，超出时提示到点会停下来问你。读不回的定时显示"自定义时间"，原串只在显示原始值里。简报页只阅读，给一个"改定时安排"的链接。

### 9.12 日历

挂在"今天"入口的页签里（`/calendar?view=day|week|month&date=YYYY-MM-DD&project=<id>`，可收藏）。数据取自 `GET /items?from=&to=`（主文档 §7.1），日界与时段按返回里的主机时区与今天；浏览器时区与主机不同时，页头加一行"按 APA 主机时间（UTC+8）显示"。只显示进行中、在等、等你决定、已完成四类，不显示建议、不做了与简报。日历页不写任何东西，切换视图、换日期、从事项详情返回、页面重新获得焦点时都重新读一次。

- **格子里写什么**：时段的开始时间（日、周视图写起止）、一行标题、状态标记（在等、等你决定、已完成、过期未办、已过截止；"要做"不标）、项目名（只在日视图）。悬停或键盘聚焦出一张只读卡：完整标题、时段、项目、阶段、截止；不显示 id，"显示原始值"打开时附上。在等是虚线边框，已完成变淡并划线，已过截止的截止标记变红；日历上没有计数红点。
- **截止**：不画进时间格，放在当天顶部的截止栏；只到日的写"截止"，有具体时刻的写"截止 18:00"。计划与截止同一天只出现一次并加"截止"标记；计划晚于截止的加"晚于截止"。
- **过期未办**：留在原来那天并标出；今天的格子顶上加一行"n 件过期未办 · 去今天页"。
- **日视图**：截止栏、未定时栏（全部列出）、时间格（0–24 点，每行半小时）。打开时滚到 07:00 或最早一条时段前一小时（取更早的）；今天有"现在"线。不到半小时的时段按半小时画。重叠的并排分栏，最多三栏，再多的在第三栏显示"+n"，点开按开始时间列出；重叠的块加"时间重叠"，不阻止也不帮你解决。没有空闲时长统计。
- **周视图**：周一开始七列；截止栏与未定时栏每列最多 3 条，多出的写"还有 n 件"，点开进当天的日视图；时间格同日视图，块里只写起止与标题。
- **月视图**：固定 6 行 × 7 列，周一开始；非本月变淡，今天高亮。每格最多 3 条，顺序是截止 → 有时段的（按开始时间）→ 未定时的（按优先级，同级按标题），已完成的在各组末尾；多出的写"还有 n 件"。
- **窄屏**（与导航收起同一断点）：日视图不变；周视图改成七天的列表，没有安排的一天写"没有安排"；月视图每格只显示条数圆点（最多 3 个）与数字，点某天进当天的日视图。
- **交互**：页头是日、周、月切换，上一段、今天、下一段，项目筛选与"新建"。视图选择记在这台浏览器，第一次打开时桌面是周视图、窄屏是日视图；地址里带了参数就以地址为准；日期不记。点一件事直接进事项详情（等你决定的顶部就是问题卡），顶部"返回刚才的页面"还原视图、日期与滚动位置。日历上没有改期控件、不做拖拽；点日、周视图的空白半小时格打开新建页，预填那天与"该格开始、往后一小时"（最晚 24:00）；月视图格子里的"+"预填那天。左右键翻段，T 回到今天，D、W、M 切换视图；焦点在输入框里时不生效。一件都没有时写"这段时间还没有排期的事"并给"新建"。

### 9.13 已完成

挂在"今天"入口的页签里，排在日历之后（`/done?week=YYYY-MM-DD`，本周不带参数；可收藏，从事项详情返回还在原周）。回答"这一周我做成了什么"。数据取自 `GET /items?phase=done` 的 `done_at`（附录 B.2）：按完成那天（主机时区）归周，周一开始；只收已完成，不收不做了的与简报（APA 自己写的），委派完成的算并标"委派"。

- **分组**：按项目，组按最近一件的完成时刻排，没归项目的排最后；组标题是项目名（点进项目页）与条数；组内最近完成的在前，每行标题（点进事项详情）与"周几 月-日"。顶上一行"共 n 件，分属 k 个项目"。不做图表。
- **切换**：上一周、本周、下一周；本周之后不能再往后翻。
- **空态**：本周写"这周还没有完成的事。做完一件，它会按完成那天记在这里。"并给"看上一周"；过去的周写"这一周没有完成的事"。
- **与今天、日历的分工**：今天只列还要做的事，底部一行完成计数指向这里；日历按计划日期排时间，已完成的在计划那天变淡划线；这里按完成那天回顾。三处都只读，改一件事都进事项详情。
- **迁移来的历史**：工作台迁移写入的事项新建时就是已完成，完成那天取迁移带来的日期（`ext.workbench.completed`，没记的取工作台最后改动那天 `ext.workbench.updated`），没有具体时刻，同一天内排在有时刻的之后。

## 10 界面语言、取值显示与手机

**界面语言**：中文与英文，在设置 › 通用里选，登录页也有切换；选择存在这台浏览器本地，没选过时跟随浏览器的语言偏好。切换的只是界面文案与日期格式：服务端返回的 `why`、`next` 原样为英文，Web 按稳定的机器码显示本地化的一句话；通知、简报与卡片文案等内核生成的内容、能力包声明的文字、账本里的用户内容都不随它变。界面文案按页面登记在各自目录的 `strings.ts`，中文与英文各一份，英文少一条时构建失败；页面代码里出现中文字面量时检查失败（`web/src/app/i18n.check.test.ts`）。

**取值按用户的话显示**：阶段、优先级、提醒类别、送达方式、权限档、规则模式、事件类型等内核取值，界面上只显示名字，名字登记在中英词表 `web/src/app/vocab.ts`，按 ID 查；内核取值的前端镜像是 `web/src/app/ids.ts`。内核新增取值而镜像没有时检查失败，镜像有而词表缺名字时构建失败。能力包可以扩展的取值查不到名字时原样显示。"显示原始值"打开后各处名字旁同时显示 ID，只存这台浏览器，默认关。

**手机**：全部页面在 360 像素宽的屏幕上可读可操作，今天、等你决定、建议和事项详情是手机上的主路径；窄屏下按钮、下拉与输入框的最小高度为 44px。窄屏上导航收成一行顶栏，只放这四个入口和"更多"；其余入口、状态灯、设置、诊断、明暗切换与退出登录在"更多"抽屉里，"更多"旁带状态小圆点；页签条可横向滑动。键盘快捷键只是桌面上的加速方式。
